# 위키 쇼츠 자동 제작

> **분류:** 미디어 · [[생활위키 목차]]

**생활위키**에 있는 글(`publish: true`)을 재료로, 유튜브 **Shorts** 대본·화면·음성을 반자동으로 뽑는 흐름을 정리한다.  
일반 촬영·Studio 조작은 [[유튜브 영상 제작]] · [[유튜브]].

사이트(예): 공개된 글은 Pages에 올라간 주소로 설명란에 링크할 수 있다.

확인일: 2026-08-07

관련: [[유튜브 영상 제작]] · [[유튜브]] · [[Cursor 사용법]] · [[현존 AI 비교]] · [[생활위키 목차]] · [[공개 규칙]]

---

## 1. 처음이면 — 툴은 이것만

해본 적 없으면 **코드·ffmpeg·API는 나중에**. 아래 세 개면 위키 → 쇼츠 첫편이 된다.

| 순서 | 툴 | 하는 일 | 어디서 |
|------|-----|---------|--------|
| 1 | [[Cursor 사용법\|Cursor]] 또는 ChatGPT 등 ([[현존 AI 비교]]) | 위키 글을 **쇼츠 대본**으로 줄이기 | PC |
| 2 | **[[CapCut]] (캡컷)** | 대본 → **TTS 음성** + 자막 + 세로(9:16) 영상보내기 | PC 또는 폰 앱 |
| 3 | **YouTube Studio** ([[유튜브]]) | mp4 업로드 · Shorts · 설명에 위키 링크 | 브라우저 |

```text
위키 .md 일부 복사
    → AI 대본
    → CapCut에서 읽고·자막·보내기
    → Studio에 올리고 사람이 재생 확인 후 공개
```

| 지금은 안 써도 됨 | 왜 |
|------------------|-----|
| OBS, 카메라 | 위키 글 쇼츠는 **글+TTS**로 충분 |
| Google Veo 등 생성형 비디오 | 위키 **정보 쇼츠에 필수 아님** (아래) |
| Remotion, ffmpeg, YouTube API | 익숙해진 뒤 “대량·무인”할 때 |
| 유료 편집기 | CapCut 무료 범위로 입문 가능 (요금·워터마크는 앱 안내 확인) |

CapCut 대신 **VN**, **Premiere** 등도 되지만, “TTS+자막+쇼츠”가 한곳에 있어 **입문 기본값으로 CapCut**을 두는 집이 많다.

### Google Veo 같은 걸 써야 하나?

**필수는 아니다.** 말하는 “자동”이 무엇이냐에 따라 툴이 갈린다.

| 원하는 자동 | 맞는 쪽 | 예 |
|-------------|---------|-----|
| **대본 → 나레이션+자막+세로 영상** (위키 팁) | 편집·TTS형 | [[CapCut]], 나중에 TTS+ffmpeg |
| **문장 → AI가 그린 영상** (장면·인물·연출) | 생성형 비디오 | Google **Veo**, 기타 텍스트→비디오 모델 |

생활위키 쇼츠는 대부분 **정보를 말해 주는 카드형**이라서:

- Veo급은 **비싸고, 글자·단축키·UI가 틀리기 쉽고**, 사실 확인이 어렵다  
- 위키 한 절 → 훅+3포인트면 **CapCut TTS**가 목적에 더 가깝다  
- “완전 무인으로 예쁜 영상만”이 목표면 생성형을 **나중에** 시험해도 됨  

생성형을 쓸 때도 **최종 공개 전 사람이 사실·면책·저작권**을 보는 편이 안전하다. ([[현존 AI 비교]] · 각 서비스 약관)

### 로컬 스크립트 샘플 (이 vault)

Veo 없이 **대본 → TTS → 세로 카드 영상** 예시를 만들어 둔 경로:

| | |
|--|--|
| 스크립트 | `미디어/scripts/make_wiki_short.py` |
| 결과 mp4 | `미디어/쇼츠-샘플/wiki-short-vscode-compare.mp4` |
| 필요 | `pip install edge-tts imageio-ffmpeg pillow` |

주제·대본을 바꾼 뒤 `python 미디어/scripts/make_wiki_short.py` 로 다시 뽑을 수 있다. CapCut UI 대체용 **입문 자동**이지, Studio 업로드·공개까지는 포함하지 않는다.

**화면:** 글자만 있으면 밋밋하다. 도구 팁 쇼츠는 **실제 캡처** 또는 UI 목업 프레임이 같이 가는 편이 좋다.  
샘플 `wiki-short-vscode-compare.mp4` 는 Playwright로 **위키 Pages·vscode.dev·데모 HTML**을 캡처해 다시 뽑을 수 있다.

| 스크립트 | 역할 |
|----------|------|
| `미디어/scripts/capture_shorts_playwright.py` | 웹 캡처 → 세로 프레임 → mp4 |
| 한계 | **데스크톱 VS Code 앱**은 Playwright로 제어 불가. 웹(vscode.dev)·사이트·로컬 HTML만 |

```powershell
python 미디어/scripts/capture_shorts_playwright.py
```

## 2. 무엇을 자동화하나

| 단계 | 자동에 가깝게 | 사람이 보는 편 |
|------|----------------|----------------|
| 글 고르기 | `publish: true` · 분류 필터 | 쇼츠에 맞는 주제인지 |
| 대본 압축 | AI로 훅+3포인트+CTA | 사실·면책·과장 여부 |
| 음성 | TTS | 발음·속도·톤 |
| 화면 | 템플릿+자막 렌더 | 오탈자·민감 정보 |
| 업로드 | API·예약(선택) | **공개 버튼·썸네일·제목** |

예전에 정리한 감각과 같게: **생성은 반자동, 최종 공개는 수동**이 안전하다.

```text
생활위키 .md (publish: true)
        ↓ 추출·요약
쇼츠 대본 (15~45초 분량)
        ↓ TTS + 자막/카드
세로 mp4 (1080×1920)
        ↓ 검토
[[유튜브]] Shorts 업로드
        ↓ 설명란
위키 글 URL + 면책
```

## 3. 쇼츠에 잘 맞는 위키 글

| 잘 맞음 | 신중 |
|---------|------|
| 도구 팁 ([[VS Code 사용법]], [[Git 사용법]], [[텔레그램]]…) | [[위고비]]·[[마운자로]]·진단성 건강글 |
| 체크리스트·단축키·비교 표 한 줄 | [[코인 현물과 선물]]·투자 확정톤 |
| “3가지만”으로 자를 수 있는 글 | 긴 설치 전체 로그 |

규칙 감각:

1. 원문 frontmatter `publish: true` 만 후보  
2. Shorts 한 편 = **한 가지 약속** (예: “Compare Active File With 쓰는 법”)  
3. 설명란 첫머리에 **원문 링크** + 필요 시 “의료/투자 권유 아님”

## 4. 대본 템플릿 (위키 → 말)

AI([[Cursor 사용법]]·[[현존 AI 비교]])에 넣을 프롬프트 골격:

```text
다음 마크다운은 생활위키 글이다. YouTube Shorts용 한국어 대본을 작성해라.
- 길이: 말하기 25~40초
- 구조: (1) 훅 1문장 (2) 포인트 3개 (3) 위키에서 더 보기 CTA
- 원문의 면책·금지는 삭제하지 말고 짧게 유지
- 과장·보장·의료/투자 조언 금지
- 화면용 짧은 자막 문장도 줄바꿈으로 따로

[여기에 본문 또는 § 일부 붙여넣기]
```

출력 예 구조:

| 초 | 말 | 화면 자막 |
|----|-----|-----------|
| 0–3 | 훅 | 큰 글씨 한 줄 |
| 3–30 | 포인트 1·2·3 | 불릿 또는 카드 |
| 끝 | “자세한 건 생활위키” | URL 또는 검색 키워드 |

표·코드가 긴 글은 **§ 하나만** 잘라 넣는 편이 낫다. (예: VS Code 파일 비교 절만)

## 5. 첫 편 따라하기 (CapCut)

1. 위키에서 짧은 절 하나 복사 (예: [[VS Code 사용법]] 파일 비교)  
2. Cursor/ChatGPT에 [[#4. 대본 템플릿 (위키 → 말)]] 프롬프트 + 붙여넣기 → 대본 받기  
3. CapCut 설치 → 새 프로젝트 → 비율 **9:16**  
4. 텍스트 붙여넣고 **텍스트 읽어주기(TTS)** / 음성 생성 (메뉴 이름은 버전마다 `텍스트 음성`·`TTS` 등으로 검색)  
5. 자동 자막 또는 문장마다 텍스트 카드  
6. 길이 맞게 자르기 → **내보내기** 1080p  
7. [studio.youtube.com](https://studio.youtube.com) → 업로드 → Shorts로 분류되는지 확인 → 설명에 위키 URL → **일부 공개**로 본인만 본 뒤 공개  

막히면 CapCut 안 검색창에 `TTS`, `자막`, `비율`만 쳐도 된다.

## 6. 반자동 파이프라인 옵션 (익숙해진 뒤)

### A. 최소 (도구 거의 없음)

1. 글에서 3줄 복사  
2. AI로 대본  
3. CapCut 등에서 TTS·자막·세로 템플릿  
4. Studio에 손수 업로드  

자동화 비율 낮음, 실패 적음.

### B. 스크립트형 (로컬)

| 조각 | 역할 |
|------|------|
| 추출 | `publish: true` 노트 목록, 본문에서 `#`·표 요약 |
| TTS | Edge TTS 등 (라이선스·품질 확인) |
| 영상 | ffmpeg로 배경+자막 burn-in, 또는 Remotion 등 |
| 메타 | 제목·설명·태그·위키 URL을 JSON으로 저장 |
| 업로드 | YouTube Data API (OAuth). **업로드 ≠ 공개**로 두고 Studio에서 공개 |

`private/`·토큰·`.env`는 커밋 금지 ([[GitHub]] Secrets 등).

### C. 노션·시트 큐

| 열 | 예 |
|----|-----|
| 원문 경로 | `작성-지식/VS Code 사용법.md` |
| 상태 | 대기 / 렌더됨 / 검토 / 공개 |
| 대본 | … |
| mp4 경로 | … |
| Studio URL | … |

[[Cursor 사용법]] Agent로 “대기 행 하나 렌더”만 반복해도 반자동이 된다.

## 7. 화면 구성 (위키 쇼츠 톤)

| 요소 | 감각 |
|------|------|
| 비율 | 1080×1920 |
| 배경 | 단색·약한 그라데이션, 또는 위키/IDE 화면 일부 (비밀번호 없게) |
| 글자 | 한 화면 한 메시지. 작은 본문 전체 금지 |
| 브랜드 | “생활위키”를 코너에 — [[유튜브 영상 제작]]의 채널 통일 |
| 끝 | 사이트·검색어 CTA |

건강·금융 글이면 **화면에도** “정보일 뿐 / 상담 아님” 한 줄.

## 8. 업로드 · 위키와 연결

| 항목 | 감각 |
|------|------|
| 제목 | 훅 + 키워드. 원문 제목 그대로 길게 붙이지 않기 |
| 설명 | 1) 한 줄 요약 2) **원문 URL** 3) 면책 4) 관련 재생목록 |
| 해시태그 | `#Shorts` 및 주제. 도배는 피함 |
| 공개 | 처음엔 **일부 공개/예약** → 확인 후 공개 |
| 위키 쪽 | 해당 `.md` 관련에 “쇼츠 있음” 또는 설명만 Studio에 — 강제는 아님 |

반복·복제만 많은 채널은 추천·수익에서 불리할 수 있다. **같은 템플릿이라도 포인트가 글마다 다르게**.

## 11. 정리

처음에는 **AI(대본) + CapCut(TTS·자막·세로) + YouTube Studio(업로드)** 만 쓴다.  
“여기 있는 컨텐츠 자동 쇼츠”는 그다음이 **위키 요약 → 렌더 → 검토 후 공개**이고, 스크립트·API는 선택이다.

## 면책

> **면책**  
> - **완전 무인·수익 보장 파이프라인이 아니다.** 최종 공개는 사람 확인을 권장.  
> - 건강·금융·법률 글은 Shorts로 줄이면 **오해·가이드라인** 위험이 크다. 면책·“상담 아님”을 빼지 말 것.  
> - TTS·음원·폰트·템플릿 라이선스, YouTube 스팸·반복 콘텐츠 정책을 **스스로** 확인.  
> - API 키·업로드 토큰은 [[Git 사용법]]처럼 비밀로.
