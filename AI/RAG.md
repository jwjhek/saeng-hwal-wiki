# RAG

> **분류:** AI · [[생활위키 목차]]

**RAG**(Retrieval-Augmented Generation, 검색 증강 생성)는 질문에 답하기 **직전**에 관련 문서를 **찾아 붙인 뒤** LLM이 글을 쓰게 하는 방식이다.  
모델 가중치를 다시 학습하지 않고도, **내 PDF·위키·규정**처럼 학습에 없는 자료를 근거로 쓸 수 있다.

확인일: 2026-08-27  
라이브러리·제품 이름은 빨리 바뀐다. 이 글은 **흐름**이고, 구현은 각 도구 문서가 우선이다.

관련: [[LLM Wiki]] · [[NotebookLM 사용법]] · [[젬마]] · [[현존 AI 비교]]

---

## 1. 개요

| 항목 | 설명 |
|------|------|
| 무엇 | **검색**으로 근거를 고르고, 그 텍스트를 프롬프트에 넣어 **생성** |
| 쓰는 이유 | LLM만으로는 회사 문서·최신 공지·사내 API를 **모름**. 미세조정은 비싸고 느림 |
| 한 질의 | 보통 **상태를 안 남김**. 다음에 같은 질문을 해도 다시 검색함 |
| 무엇이 아님 | 모델을 통째로 재학습하는 미세조정, ingest 때 위키를 만드는 [[LLM Wiki]] |

```text
질문
 ↓
(선택) 질문 다듬기 · 하이브리드 검색
 ↓
문서 조각(청크) 몇 개 검색
 ↓
조각 + 질문을 LLM에 넣음
 ↓
답 (+ 가능하면 출처)
```

클라우드 챗의 **파일 업로드·내 데이터** 도 같은 축인 경우가 많다. 제품 UI만 다를 뿐, 뒤는 RAG에 가깝다 → [[OpenAI Platform]] 임베딩·파일 검색, [[NotebookLM 사용법]].

---

## 2. 부품

| 부품 | 하는 일 |
|------|---------|
| **원문** | PDF, HTML, `.md`, DB 행. **권한**이 있는 것만 색인해야 함 |
| **청크** | 긴 글을 토큰 단위로 자름. 너무 짧으면 맥락이 없고, 너무 길면 검색이 둔해짐 |
| **임베딩** | 글·질문을 숫자 벡터로. “뜻이 가까운 문장”을 찾기 위함 |
| **색인** | 벡터 DB, 또는 키워드 검색(BM25)과 **같이** 쓰는 집이 많음 |
| **리트리버** | top-k 조각을 고름. 재순위(rerank)를 붙이기도 함 |
| **LLM** | 붙인 조각을 읽고 답함. 로컬이면 [[Ollama]] + [[젬마]] 등 |
| **출처** | 어느 파일·몇 쪽인지. 감사·검수에 필요 |

임베딩 모델과 생성 모델은 **달라도 된다.** 작은 임베딩 + 중간 생성 조합이 흔하다.

---

## 3. 잘 되는 일 / 자주 깨지는 일

| 잘 되는 편 | 깨지기 쉬운 편 |
|------------|----------------|
| 규정·매뉴얼에서 **조항을 찾아** 요약 | 원문에 **없는 숫자**를 지어 냄 (검색이 빗나가면 더 심함) |
| “이 폴더 기준으로 답해” | 청크가 표를 잘라 **한 칸만** 가져옴 |
| 출처를 붙여 사람이 확인 | 오래된 색인 + 새 문서 = **틀린 최신** |
| 내부망에서 자료가 밖으로 안 나가게 | 권한 없는 파일이 색인되면 **검색으로 유출** |

RAG를 켜도 **환각은 남는다.** 모델이 조각을 무시하거나, 조각을 오독한다. “우리 문서에만 근거한다”는 프롬프트는 도움이 되지만 보장이 아니다.

평가할 때 볼 것: **맞춘 청크인가**, **인용한 문장이 원문에 있는가**, **권한 밖을 안 읽었는가**.

## 4. 비슷한 것과 구분

| | RAG | 컨텍스트에 전부 넣기 | 미세조정 | [[LLM Wiki]] | [[NotebookLM 사용법]] |
|--|-----|---------------------|----------|--------------|----------------------|
| 지식 넣는 때 | **질문할 때** 검색 | 매번 긴 창에 첨부 | **학습할 때** 가중치 | **ingest 때** 위키 `.md` | 노트북에 소스 업로드 |
| 문서가 자주 바뀜 | 색인만 갱신하면 됨 | 창 길이·비용 | 다시 학습 | 위키를 다시 쓰게 함 | 소스 다시 넣기 |
| 교차 링크 | 약함 (조각 단위) | 없음 | 모델 안에 섞임 | `[[링크]]` | 노트북 안 |
| 규모 | 대량 코퍼스에 유리 | 짧은 묶음 | 말투·도메인 습관 | 큐레이션된 주제 | 주제별 노트북 |

배타적이지 않다. 위키로 개념을 쌓고, 원문 검색은 RAG로 두는 **하이브리드**가 흔하다 → [[LLM Wiki]] §2.

전자정부 표준프레임워크 **5.0** 안내에 AI RAG 예제가 있다. 사업에 넣을지는 RFP·보안이 가른다 → [[전자정부프레임워크]].

파이썬 쪽에서 오케스트레이션으로 **LangChain** · **LlamaIndex** 이름이 자주 나온다. 버전 변화가 커서 이 글에 API를 고정하지 않는다 → [[Python 학습과 패키지]].

## 5. 로컬에서

민감 문서를 클라우드 챗에 안 올리는 집이면:

1. 문서를 청크·임베딩 (로컬 임베딩 모델 또는 허용된 API)  
2. 생성은 [[Ollama]] 로 [[젬마]] · Llama · Qwen 등  
3. 앱은 간단한 스크립트·[[API]] 서버·에디터 확장  

VRAM·RAM은 생성 모델이 대부분을 먹는다. `26B` 읽는 법은 [[파라미터 수]]. 색인 용량은 따로 잡는다.

[[MCP]] 로 “폴더를 검색하는 도구”를 붙이는 것도, 에이전트 입장에선 RAG와 같은 일에 가깝다.

## 6. 도입 전에

- [ ] **어떤 폴더**가 색인되는지 (개인정보·비밀은 빼기)  
- [ ] 답이 **출처**를 보여 주는가  
- [ ] 문서가 바뀌면 색인을 **언제** 다시 돌리는가  
- [ ] LLM만 쓸 때와 **A/B**로 틀린 답을 비교해 봤는가  
- [ ] 클라우드면 약관·학습 여부, 로컬이면 라이선스([[젬마]] 카드)

---

## 면책

> **면책**  
> RAG는 검색이 빗나가거나 원문이 틀리면 답도 틀린다. 의료·법률·금융 결정의 근거로 쓰지 않는다.  
> 벡터 DB·임베딩·프레임워크 API는 **수시로 바뀐다.** 공식 문서가 우선이다.  
> 색인 범위·접근 제어는 운영자 책임이다.
