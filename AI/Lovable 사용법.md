# Lovable 사용법

> **분류:** AI · [[생활위키 목차]]

**Lovable**(한국어로 흔히 **러버블**)은 브라우저에서 **말로 웹앱을 만들고** 배포하는 AI 개발 플랫폼이다.  
프론트(화면)뿐 아니라 백엔드·DB·로그인까지 한 프로젝트로 붙이는 쪽을 표방한다. 결과물은 **실제 코드**이고, GitHub·GitLab과 동기화할 수 있다.

에디터 안에서 기존 저장소를 고치는 [[Cursor 사용법]]·[[GitHub Copilot 사용법]]과 **자리가 다르다.** 빈 화면에서 **앱을 통째로 뽑는** 층에 가깝고, [[바이브 코딩]] 스펙트럼의 **브라우저 전체 생성** 쪽에 자주 놓인다.

공식: [https://lovable.dev](https://lovable.dev) · 문서: [https://docs.lovable.dev](https://docs.lovable.dev) · 요금: [pricing](https://lovable.dev/pricing)

확인일: 2026-08-14  
플랜·크레딧·UI는 자주 바뀐다. **공식 가격표·문서가 우선.**

관련: [[바이브 코딩]] · [[Cursor 사용법]] · [[현존 AI 비교]]

---

## 1. 개요

| 항목 | 설명 |
|------|------|
| **무엇** | 자연어(채팅)로 **웹 애플리케이션**을 생성·수정·배포 |
| **결과** | React 등 **읽을 수 있는 코드**. 플랫폼만의 잠금 상자가 아님(문서: 코드 소유) |
| **백엔드** | 기본 **Lovable Cloud**(Supabase 계열: DB·인증·스토리지·함수). 자기 **Supabase** 프로젝트에 연결할 수도 |
| **배포** | Lovable 호스팅(`lovable.app` 등) + 커스텀 도메인(유료 쪽). Git 동기화 후 Netlify 등 **바깥 호스팅**도 |
| **아닌 것** | 로컬 마크다운 위키·기존 대형 레포 리팩터의 주 도구. 그건 [[Cursor 사용법]] |

```text
아이디어를 채팅으로 설명
 ↓
미리보기 앱 생성 (화면 + 필요 시 DB·로그인)
 ↓
대화로 고치기 · (유료) 코드 보기
 ↓
게시 / Git 동기화 / 바깥에서 이어 개발
```

「10분이면 완성 SaaS」는 **마케팅에 가깝다.** 결제는 되고 보안·예외는 구멍인 데모가 흔하다.

## 2. Cursor·Copilot과 언제 나누나

| | **Lovable** | **[[Cursor 사용법]]** | **[[GitHub Copilot 사용법]]** |
|--|-------------|----------------------|------------------------------|
| 무대 | **브라우저** | 로컬 에디터 | IDE 플러그인 |
| 시작 | 빈 앱·랜딩·MVP | **이미 있는** 폴더 | 열린 파일 완성 |
| 강점 | 화면+백엔드 **한 번에** | diff 검수, 위키·기존 코드 | Tab 완성·PR |
| 약점 | 크레딧, 생성 코드 이해 부족 | 처음부터 UI를 말만으로 뽑기는 느림 | 프로젝트 통째 생성은 약함 |

같이 쓰는 집: Lovable로 **뼈대** → Git 동기화 → Cursor에서 **검수·기능**.  
마크다운 노트·Quartz 사이트는 Lovable이 아니라 Cursor·[[Git 사용법]]·[[GitHub]] 쪽이 맞다.

Bolt·v0·Replit Agent도 **브라우저에서 앱 생성** 축이다. 스택·요금·Git 연동만 다르다. 도구를 바꿔도 [[바이브 코딩]]처럼 **코드를 안 읽으면** 같은 위험이다.

---

## 3. 쓰는 이유

| 상황 | Lovable |
|------|---------|
| 주말 **프로토타입**·해커톤 | 화면이 빨리 나옴 |
| 기획·디자인이 **클릭 가능한 시안**이 필요할 때 | 정적 목업보다 설득력 |
| 비개발자가 **자기용 작은 도구** | 설치 없이 채팅 |
| 개발자가 **보일러플레이트 생략** | 로그인·CRUD 뼈대 |
| 결제·의료·대량 개인정보 **본 서비스** | **부적합에 가깝다** — 생성 코드를 사람이 보안 검토하기 전 |

카파시가 말한 바이브 코딩의 **주말·버릴 프로젝트**와 잘 겹친다. 회사 핵심 API에 바로 붙이지 않는 편이 안전하다.

## 4. 크레딧·플랜 (감만)

확인일 기준 문서 방향. **숫자·달러는 공식 표가 맞다.**

| 플랜 | 방향 |
|------|------|
| **Free** | 하루 **빌드 크레딧 5** (달력월 **30**에서 컷). Cloud·AI 소량 지급. 체험·작은 프로토타입 |
| **Pro** | 월 구독 크레딧(문서 예: **100부터**) + 일일 빌드 5(월 상한 없음). 롤오버·충전. 개인·소규모 |
| **Business** | Pro에 가깝게 **거버넌스**(SSO, 역할, 학습 opt-out 등). 크레딧만 더 주는 플랜이 아님 |
| **Enterprise** | 용량·감사·SCIM 등 계약 |

일일 빌드 크레딧은 **UTC 0시**에 리셋되고 **이월되지 않는다**는 안내가 있다.  
채팅 한 번이 크레딧을 쓰고, **작은 스타일 수정 < 큰 기능 생성**인 경우가 많다.

설정 → **Plans & credit usage**에서 사용량을 본다. 이 글은 **가입 권유가 아니다.**

## 5. 프로젝트 흐름

워크스페이스(팀·크레딧 풀) 안에 **프로젝트 = 앱 하나**.

1. 계정 → 새 프로젝트  
2. **무엇을 만드는지** 한 덩어리로 적기 (사용자, 화면, 로그인 여부, 데이터가 뭔지)  
3. 미리보기에서 클릭해 보고, **한 가지씩** 고쳐 달라고 하기  
4. 필요하면 Cloud(또는 자기 Supabase)로 로그인·테이블  
5. **Update / Publish** 로 공개 URL  
6. (권장) **Project settings → Git** 으로 GitHub 또는 GitLab **양방향 동기화**

Git은 필수가 아니다. 많은 사람은 Lovable 안에서만 만든다.  
코드만 필요하면 유료 쪽 **Code editor → Download codebase**.

프롬프트는 크게:

| 하면 나은 편 | 피하기 쉬운 편 |
|--------------|----------------|
| 역할·화면 목록·금지(결제 없음 등) | “멋진 SNS 만들어줘” 한 줄 |
| 한 번에 **기능 하나** | 열 가지를 한 메시지에 |
| 깨진 화면을 **재현 절차**와 함께 | “안 돼요”만 |
| 비밀 키를 **채팅에 안 넣기** | API 키·주민번호 붙여 넣기 |

## 6. Cloud · Supabase · Git

| 구성 | 설명 |
|------|------|
| **Cloud (기본)** | 내장 백엔드. DB·Auth·파일·엣지 함수. 따로 계정 없이 시작 |
| **자기 Supabase** | 이미 프로젝트가 있거나 **데이터 소유**를 대시보드에서 보고 싶을 때 연결 |
| **Git 동기화** | Lovable에서 고친 것이 원격에 커밋되고, 동기화 브랜치에 푸시하면 **다시 Lovable에** 반영 (문서: 양방향) |
| **바깥 배포** | 동기화한 저장소를 Netlify·Cloudflare Pages 등에 연결. SPA면 **새로고침 404** 리라이트 필요 |

프론트만 Lovable, DB는 Cloud — 기본 조합.  
백엔드를 옮기면 Cloud 전용 기능이 **안 따라올 수** 있다. 문서의 마이그레이션을 본다.

환경 변수 이름(예: `VITE_SUPABASE_URL`)은 코드에 보이지만 **키 값은 공개 Git에 올리지 않는다.** [[Git 사용법]] `.gitignore` · [[GitHub]].

## 7. 보안·검수

플랫폼은 SOC 2·ISO 27001·GDPR 등을 **자기 인프라**에 대해 내세운다.  
**내가 만든 앱의 버그**는 별개다.

| 위험 | 할 일 |
|------|--------|
| 인증·권한 | 남의 데이터가 보이는지 **계정 두 개로** 확인 |
| SQL·RLS | 테이블이 열려 있지 않은지 |
| XSS·공개 URL | 입력값이 그대로 HTML에 |
| 비밀 | 프롬프트·프론트 번들에 키 금지 |
| 의존성 | 이상한 패키지·라이선스 |
| 결제·개인정보 | 생성 코드만으로 **상용 금지**에 가깝다 |

유료 플랜의 **코드 모드**로 읽고, 가능하면 Cursor에서 diff를 본다. [[바이브 코딩]] §5와 같다.

## 8. 위키 글·기존 코드와

| 목적 | 도구 |
|------|------|
| Quartz·GitHub Pages **위키 md** | [[Cursor 사용법]] · [[Obsidian 사용법]] · [[Quartz 사용법]] |
| Java·Spring·SQL **기존 코드** | Cursor · Copilot · [[Spring과 Spring Boot 학습]] |
| “이런 화면이면 되겠다” **시안** | Lovable (또는 디자인 툴) |
| 개념 공부 | 생성 코드를 **읽기**. 안 읽으면 실력이 안 남음 — [[디자인 패턴]] |

Lovable 결과물을 위키에 **그대로 붙여 공개**하지 않는다. 라이선스·개인정보·환각 UI 카피가 섞일 수 있다.

## 9. 실전 체크

- [ ] 버릴 수 있는 **프로토타입**인가, 본 서비스인가  
- [ ] 공식 [pricing](https://lovable.dev/pricing)의 **크레딧**을 봤는가  
- [ ] 프롬프트에 **키·개인정보**가 없는가  
- [ ] 로그인·권한을 **두 계정으로** 눌러 봤는가  
- [ ] Git 동기화 또는 코드 다운로드로 **백업**이 있는가  
- [ ] 이어서 고칠 때 [[Cursor 사용법]]에서 **diff를 읽을** 계획인가
