# Freqtrade 사용법

> **분류:** 금융 · [[생활위키 목차]]

**Freqtrade**는 Python으로 만든 **오픈소스 암호화폐 자동매매 봇**이다.  
커뮤니티에서는 **freqtrading**이라고도 부른다. 공식 이름·저장소는 **Freqtrade**다.

캔들(봉)과 전략 코드로 **매수·매도 조건을 반복 실행**하는 도구이지, 거래소 옆에 컴퓨터를 붙여 나노초 단위로 호가를 먹는 **고빈도매매(HFT)** 가 아니다.  
백테스트 숫자가 곧 실전 수익이 아니다.

공식: [https://www.freqtrade.io](https://www.freqtrade.io) · 문서: [stable](https://www.freqtrade.io/en/stable/) · 코드: [GitHub freqtrade/freqtrade](https://github.com/freqtrade/freqtrade) (GPL-3.0)

확인일: 2026-08-14  
버전은 `2026.6`처럼 **월 단위**로 자주 바뀐다. 설치·거래소 목록은 **stable 문서**가 우선.

관련: [[코인 현물과 선물]] · [[Bybit]] · [[재정거래]] · [[Docker 사용법]]

---

## 1. 개요

| 항목 | 설명 |
|------|------|
| **무엇** | 전략(Python) + 설정(JSON)으로 거래소 API에 **주문**을 넣는 봇 |
| **연결** | [CCXT](https://github.com/ccxt/ccxt)로 여러 거래소. **공식 지원 목록**만 비교적 안전 |
| **조종** | **FreqUI**(웹) · [[텔레그램 봇]] |
| **연습** | **Dry-run**(모의 체결)을 먼저. 실전(Live)은 그다음 |
| **먼저 볼 것** | 현물·선물·청산은 [[코인 현물과 선물]]. 봇은 그걸 **자동으로 눌러 줄 뿐** |

공식 문서 면책과 같다. **잃어도 되는 돈이 아니면 쓰지 않는다.** 코딩·Python 기초가 없으면 전략을 검증하기 어렵다.

```text
전략 작성 (IStrategy)
 ↓
과거 봉 받기 (download-data)
 ↓
백테스트 → (선택) 하이퍼옵트
 ↓
Dry-run 으로 며칠~몇 주 관찰
 ↓
(이해한 뒤에만) Live · 소액
```

---

## 2. HFT·「먹튀 봇」과 다른 점

| | Freqtrade | 흔히 말하는 HFT |
|--|-----------|-----------------|
| 속도 | REST API, 분·시간 **봉** 전략이 흔함 | 초저지연·호가창 마이크로초 |
| 위치 | 집 PC·VPS | 거래소 코로케이션에 가깝 |
| 기대 | 규칙 반복·기록·실험 | 스프레드를 **기계가 먼저** 먹음 |

유료 「월 수익률 보장 전략 파일」·남의 `config.json`(API 키 포함)을 받는 것은 **피싱·사기**에 가깝다.  
[[재정거래]]처럼 화면에 보이는 차이도, 봇이 들어가면 **이미 늦은** 경우가 많다.

## 3. 할 수 있는 것 (공식 기능)

| 기능 | 한 줄 |
|------|--------|
| **전략** | pandas로 지표·진입·청산. 예제 저장소는 **영감용**이지 검증된 수익이 아님 |
| **데이터** | 거래소 과거 봉 다운로드 |
| **백테스트** | 받은 봉으로 과거 시뮬레이션 |
| **하이퍼옵트** | 진입·청산·ROI·손절 등 숫자를 탐색 (과적합 주의) |
| **페어 목록** | 고정 목록 또는 거래량 상위 등. **블랙리스트** |
| **Dry-run / Live** | 가상 잔고 vs 실제 주문 |
| **FreqAI** | 내장 ML 모듈. **학습 ≠ 수익**. 자원·과적합 부담이 큼 |
| **보호** | 연속 손실 후 휴식 등 플러그인 |

선물·레버리지는 **일부 거래소만**. 문서는 [leverage](https://www.freqtrade.io/en/stable/leverage/)를 읽으라고 한다. 청산은 사람 손으로 할 때와 **같은 위험**이다.

---

## 4. 거래소

목록은 시점마다 바뀐다. 확인일 기준 **공식 현물 예:** Binance, Bybit, OKX, Gate.io, Kraken, Bitget 등.  
**선물 예:** Binance, Bybit(격리), OKX, Gate.io, Kraken 등.

- 해외 거래소 실무: [[Bybit]] (Freqtrade도 Bybit 현물·선물 **격리**를 공식 표에 넣음. 현물 거래소 손절 주문은 거래소마다 다름)
- [[업비트]] 등 **국내 원화 현물**은 공식 지원 표에 **없는 경우가 많다.** CCXT에 이름이 있어도 **손절·체결·약관이 보장되지 않음**
- 거래소별 특수 설정: [Exchange notes](https://www.freqtrade.io/en/stable/exchanges/)

거주국에서 그 거래소를 **써도 되는지**, API 권한(출금 금지)은 **본인이** 확인한다.

---

## 5. 설치 방향

공식은 **Docker를 권장**. 최소 사양 예: 클라우드 2 vCPU · RAM 2 GB · 디스크 1 GB (문서 기준). 하이퍼옵트·FreqAI는 **훨씬 더** 필요하다.

| 방법 | 메모 |
|------|------|
| **Docker Compose** | [[Docker 사용법]]. 공식 [Docker Quickstart](https://www.freqtrade.io/en/stable/docker_quickstart/) |
| **Python 직접** | 3.11+ · venv · TA-Lib. [[파이썬 개발 툴]] · [[Python 학습과 패키지]] |

명령·파일 이름은 버전에 따라 다르다. **복사한 블로그 한 줄보다 공식 Quickstart.**

자주 쓰는 하위 명령 개념:

| 명령 (개념) | 하는 일 |
|-------------|---------|
| `new-config` | 설정 마법사. **Dry-run을 켜고** 시작하라는 질문이 있음 |
| `new-strategy` | 전략 뼈대 |
| `download-data` | 봉 받기 |
| `backtesting` | 과거 검증 |
| `hyperopt` | 파라미터 탐색 |
| `trade` | Dry-run 또는 Live 봇 가동 |
| `webserver` | FreqUI |

설정·키·DB는 **공개 Git에 올리지 않는다.**

## 6. 전략이 하는 일

전략은 보통 `IStrategy`를 상속한 Python 클래스다. 큰 흐름만:

```text
봉 데이터
 ↓
지표 계산 (populate_indicators)
 ↓
진입 조건 (populate_entry_trend)
 ↓
청산 조건 (populate_exit_trend)
 + ROI 표 · 손절 · 트레일링
```

백테스트에만 있는 옵션(같은 페어를 여러 번 겹쳐 사는 **포지션 스택** 등)은 **Dry/Live에 그대로 안 옮겨질 수** 있다. 문서도 실전과 가까운 설정으로 다시 보라고 한다.

남이 준 `.py`는 **코드를 읽고**, 출금·외부 URL·키 전송이 없는지 본다.

---

## 7. 백테스트가 거짓말하는 이유

| 함정           | 설명                                    |
| ------------ | ------------------------------------- |
| **과적합**      | 그 구간에만 맞는 숫자. 하이퍼옵트로 **승률만** 고르면 더 심함 |
| **미래 정보**    | 잘못된 리샘플·시프트                           |
| **수수료·슬리피지** | 설정이 실전보다 낙관적이면 이익이 부풀음                |
| **유동성**      | 작은 알트는 호가가 전략을 못 받음                   |
| **결측 봉**     | 거래소가 빈 봉을 안 주면 봇이 이전 종가로 채우기도 함 (FAQ) |
| **선별 페어**    | 이긴 페어만 넣고 돌리면 **좋아 보이는** 리포트          |

공식도 **이긴 페어만 쓰면 과적합**이라고 적는다. 백테스트 후 **Dry-run을 길게** 보라는 이유다.

---

## 8. Dry-run과 Live

| | Dry-run | Live |
|--|---------|------|
| 돈 | 가상 잔고 (`dry_run_wallet` 등) | 거래소 실제 잔고 |
| 주문 | 시뮬 | API로 **진짜 체결** |
| DB | `tradesv3.dryrun.sqlite` 쪽이 기본 | `tradesv3.sqlite` 쪽 |
| Bybit 추가 | 거래소 **Demo** API를 쓰는 설정도 문서에 있음 ([[Bybit]] Demo와 별개로, Freqtrade 쪽 `exchange.demo_trading`) | 실계정 키 |

Dry-run도 **체결가·대기열**이 실전과 100% 같지는 않다.  
「Dry에서 이겼으니 Live 풀배팅」은 흔한 실패 패턴이다.

Live로 넘어갈 때:

- 출금 권한 **없는** API 키  
- 가능하면 **IP 제한**  
- 현물이면 현물 권한만. 선물은 레버·격리부터 [[코인 현물과 선물]]  
- **소액** · `max_open_trades`를 작게  
- VPS가 꺼지면 포지션만 남는 상황을 가정  

키·텔레그램 토큰은 `private/` 또는 로컬만. 이 위키에는 넣지 않는다.

## 9. 보안·운영

| 항목 | 설명 |
|------|------|
| **키** | 유출 = 잔고 조작. 출금 권한은 켜지 않는 집이 많음 |
| **Git** | `user_data/config.json` · `.env` 커밋 금지 |
| **텔레그램** | 봇 토큰·채팅 ID가 있으면 원격으로 정지·상태 조회. 채팅방을 **공개 채널에 두지 말 것** ([[텔레그램 봇]]) |
| **웹 UI** | 비밀번호·방화벽. 인터넷에 그냥 열지 않음 |
| **24시간** | 전기·도커·거래소 점검. 봇이 죽은 동안 **손절이 안 나갈 수** 있음 (거래소 손절 지원 여부는 거래소마다) |
| **세금** | 봇이 낸 체결도 **본인 거래**. 세무 자문 아님 |

## 10. 흔한 오해

| 말 | 실제 |
|----|------|
| 「AI 봇이라 돈을 번다」 | FreqAI·하이퍼옵트는 **도구**. 수수료를 못 이기면 손실 |
| 「백테스트 200%」 | 과적합·비용 누락 가능성부터 의심 |
| 「카피 전략 공유」 | 그 구간·그 페어·그 수수료에서만 맞을 수 있음 |
| 「업비트도 그냥 됨」 | 공식 표를 본다. 안 되면 **억지로 우회하지 않음** |
| 「재정거래 봇」 | Freqtrade 기본은 **한 거래소 전략 봇**. 거래소 간 이체 재정([[재정거래]]·[[코인 트래블룰]])과는 별 층 |

## 11. 실전 전에 물을 것

- [ ] [[코인 현물과 선물]]의 주문·(선물 시) 청산·펀딩을 설명하는가  
- [ ] 공식 문서의 **지원 거래소·모드**와 내 설정이 같은가  
- [ ] 백테스트 **수수료**를 실전에 가깝게 넣었는가  
- [ ] Dry-run을 **다른 구간·다른 장**에서도 봤는가  
- [ ] API에 **출금 권한이 꺼져** 있는가  
- [ ] 키·설정이 공개 저장소에 없는가  
- [ ] 꺼진 봇·거래소 점검 때 남은 포지션 계획을 갖고 있는가  
- [ ] 생활비·대출로 돌리지 않는가

## 12. 정리

1. Freqtrade(freqtrading) = **규칙 기반 코인 봇**. HFT가 아니다.  
2. 순서: 전략 → 데이터 → 백테스트 → Dry-run → (이해한 뒤) 소액 Live.  
3. 예쁜 리포트는 **과적합**일 수 있다.  
4. 개념은 [[코인 현물과 선물]], 거래소 UI는 [[Bybit]], 컨테이너는 [[Docker 사용법]].

## 면책

> **강한 면책**
> - 교육용 일반 정보이며 **투자·자동매매·가입·수익 권유가 아니다.**
> - 봇·선물·레버리지는 **원금 전액(구조에 따라 그 이상)** 손실 위험이 있다.
> - 공식 소프트웨어도 **결과를 보장하지 않는다.** 이 글도 손실에 책임지지 않는다.
> - 거주국 **법률·세금·거래소 이용·API 약관**을 스스로 확인한다.
> - 이 글은 **우회 상장·불법 송금·출금 권한 우회·타인 계정 자동화**를 안내하지 않는다.
> - 명령·거래소 목록·UI는 **버전·공지**가 우선이다.
