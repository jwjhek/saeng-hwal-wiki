# Bybit

> **분류:** 금융 · [[생활위키 목차]]

[Bybit](https://www.bybit.com)은 암호화폐 **현물·파생(무기한·만기)·일부 옵션** 등을 제공하는 해외 거래소 중 하나다. 
현물·선물 **개념**은 [[코인 현물과 선물]]을 먼저 본다. 
국내 거래소에서 코인을 빼거나 넣을 때 정보 교환·상대 제한은 [[코인 트래블룰]].

확인일: 2026-08-10 
공식 안내는 [헬프센터](https://www.bybit.com/en/help-center) · [Demo Trading FAQ](https://www.bybit.com/en/help-center/article/FAQ-Demo-Trading)가 우선. UI 문구는 앱·웹·언어·시점에 따라 다르다.

---

## 1. 위치

| | Bybit |
|--|--------|
| 성격 | 글로벌 파생·현물 비중이 큰 거래소 |
| 비슷한 곳 | Binance, OKX, Bitget 등 (메뉴만 다름) |
| 국내 원화 현물 | [[업비트]] 등과 역할이 다름 |
| 연습 | **Demo Trading**(메인 추천) · **Testnet**(별도 환경) → [[#3. Demo Trading과 Testnet]] |

거래소 파산·해킹·출금 정지 리스크가 있다. **거래에 필요한 만큼만** 입금하는 습관이 흔히 언급된다 (권유 아님).

---

## 2. 사용법 개요

```text
공식 사이트/앱 가입 → 2FA·보안
 ↓
(권장) Demo Trading으로 주문·청산·UTA만 연습
 ↓
실계정: KYC(필요 시) → 입금(소액 테스트)
 ↓
Assets에서 잔고·Transfer 확인
 ↓
Spot 또는 Derivatives(USDT Perp 등)
 ↓
마진·레버·TP/SL 설정 → 주문 → Positions → 종료
 ↓
출금 전 포지션 정리 · 네트워크·주소 재확인
```

처음 순서: **Demo → 현물 소액 → (필요할 때만) Isolated 저레버 선물**.

## 3. Demo Trading과 Testnet

Bybit에는 **실돈이 아닌** 연습 환경이 둘로 나뉜다. 이름이 비슷해 헷갈리기 쉽다.

| | **Demo Trading** (데모) | **Testnet** (테스트넷) |
|--|-------------------------|------------------------|
| 목적 | **거래 UI·주문·전략** 연습 | 신규 기능·입출금·플랫폼 전반 **사전 검증**, API/개발 테스트 |
| 어디서 | **본계정(메인넷) 로그인 후** 프로필에서 Demo로 전환 | **별도 Testnet 사이트/환경** (메인 앱과 분리) |
| 시세 | 실거래와 비슷한 **라이브 시세**를 쓰는 쪽으로 안내 | 실전과 **다를 수 있음** (연습용으로 덜 추천되는 경우가 많음) |
| 계정 | 가입 시 **시뮬레이션 UTA**가 붙는다고 안내. KYC 없이 데모 가능 | Testnet 전용 계정. KYC 없이 쓰는 안내가 흔함 |
| 잔고 | 가상 자산. **Demo Funds 요청**으로 충전(한도·쿨다운은 시점별) | 테스트 자산 지급(예: 24시간에 1회 등 — 공지 확인) |
| UTA | **UTA 기준** 현물·파생 연습이 중심. UTA 밖 기능은 제한될 수 있음 | 플랫폼 기능 범위가 더 넓게 열려 있다는 설명도 있음 |
| API | 데모 전용 키 · `api-demo.bybit.com` 등 (문서 확인) | Testnet API 엔드포인트는 **데모와 다름**. 혼용 금지 |
| 실전 전환 | 화면의 **Start Live Trading** 등으로 실계정 복귀 | Testnet ≠ 실계정. 메인으로 다시 로그인 |

### 3.1 무엇을 쓸까

| 목적 | 선택 |
|------|------|
| 주문창·롱/숏·TP/SL·청산만 | **Demo Trading** |
| 봇·API로 주문 흐름만 | **Demo API** (데모 모드에서 키 발급) |
| 입출금·신규 메뉴·메인에 없는 실험 | **Testnet** |
| 수익 내기 | 어느 쪽도 **실전 성과가 아님** |

데모·테스트넷에서 잘 됐다고 **실전 동일 결과**를 기대하지 않는다. 심리·슬리피지·한도·청산 속도가 다르다.

### 3.2 Demo Trading 들어가는 법 

**웹**

1. [bybit.com](https://www.bybit.com) 로그인 
2. 우측 상단 **프로필(아바타)** 에 마우스 
3. **Demo Trading** 선택 
4. 가상 잔고가 부족하면 **Request Demo Funds / 데모 자금 받기** 
5. Spot 또는 Derivatives에서 연습 
6. 끝낼 때 **Start Live Trading**(또는 동등 문구)으로 실계정 복귀 

**앱**

1. 프로필·설정 화면에서 **Demo Trading** 입구 
2. 데모 화면인지(배너·잔고가 가상) **항상 확인** 
3. 복귀: 거래 화면 상단 등의 **Start Live Trading** 

실잔고 화면과 데모 화면을 혼동하면 실수를 한다. 전환할 때마다 **Live / Demo** 표시를 본다.

### 3.3 Testnet

- 메인 거래 연습보다 **기능·개발 검증** 쪽에 가깝다. 
- Demo FAQ에서도 “거래 연습은 Demo, 비거래·기타 테스트는 Testnet” 식으로 나눈다. 
- 주소·도메인이 메인과 **다르다**. 북마크를 섞지 말 것. 
- Testnet에서 만든 API 키를 메인·데모 URL에 넣으면 실패하거나 위험하다.

공식 비교·최신 절차: [FAQ — Demo Trading](https://www.bybit.com/en/help-center/article/FAQ-Demo-Trading) · [How to use Demo Trading](https://learn.bybit.com/en/bybit-guide/how-to-use-bybit-demo-trading/)

## 4. 가입 · 보안 (실계정)

1. **공식** 사이트/스토어 앱만 (피싱 도메인 주의) 
2. 이메일·휴대폰 등으로 계정 생성 
3. **KYC**(신원 확인) — 거주국·한도·출금·일부 상품에 영향. 데모만 쓸 때는 필수가 아닐 수 있음 
4. **2FA(OTP)** 필수에 가깝게 
5. 출금 주소 **화이트리스트**, 안티피싱 코드 
6. 시드·복구코드·고객센터 사칭 메시지 무시 

OTP 앱은 폰에 두는 경우가 많다 → [[갤럭시 폰 사용법]]. 
거주국에서 Bybit **이용 가능 여부·세금**은 스스로 확인한다.

## 5. 자산 · 입금 · 출금 · Transfer

### 5.1 Assets(자산)

| 할 일 | 어디 |
|-------|------|
| 잔고 보기 | **Assets** |
| 코인 넣기 | Deposit |
| 코인 빼기 | Withdraw |
| 계정 칸 옮기기 | **Transfer** (예: 펀딩 ↔ UTA, 현물 ↔ 파생 — 명칭은 UI 따름) |

파생을 하려면 잔고가 **UTA(통합 거래 계정)** 쪽에 있어야 하는 경우가 많다. 입금 후 Transfer를 빼먹으면 “잔고는 있는데 주문이 안 됨”이 난다.

### 5.2 입금

1. Assets → Deposit 
2. 코인·**네트워크** 선택 (ERC20 / TRC20 / BTC 등) 
3. 주소·**메모/태그**(있으면)를 받는 쪽 화면과 **한 글자씩** 대조 
4. **소액 테스트** 후 본금액 
5. 컨펌 수·지연은 네트워크·혼잡에 따라 다름 

**네트워크 불일치 = 자산 영구 손실** 위험이 크다.

### 5.3 출금

1. 열린 포지션·미체결 주문 정리(또는 증거금 여유 확인) 
2. 필요 시 UTA → 출금 가능 지갑으로 Transfer 
3. Withdraw — 네트워크·주소·메모·2FA 
4. 소액 테스트 후 본거래 

국내 거래소([[업비트]] 등)와 오갈 때는 [[코인 트래블룰]]·명의·연동을 **먼저** 확인한다.

## 6. Unified Trading Account (UTA)

Bybit **UTA**는 현물·파생 담보를 한계정에서 다루는 통합 구조다. 
데모도 현재는 **UTA 모드**로 안내되는 경우가 많다.

| 모드 | 설명 |
|------|------|
| **Isolated** | 포지션별 증거금 격리 — 연습·소액에 자주 권장되는 쪽 |
| **Cross** | 담보 공유 — 계좌 전반이 같이 위험해질 수 있음 |
| Portfolio 등 | 고급. 모르면 쓰지 않음 |

처음에는: **Isolated + 낮은 레버리지**. 
상세: [Margin modes (UTA)](https://www.bybit.com/en/help-center/article/Differences-Between-the-Margin-Modes-Under-the-Unified-Trading-Account/) 
청산은 보통 **Mark Price** 기준 → [Liquidation (UTA)](https://www.bybit.com/en/help-center/article/UTA-Trading-Rules)

## 7. 현물(Spot) 사용법

1. 메뉴 **Spot / 현물** 
2. 페어 선택 (예: `BTCUSDT`) 
3. 잔고가 해당 계정에 있는지 확인 (없으면 Transfer) 
4. **Buy / Sell** 
 - Limit(지정가): 가격·수량 입력 후 대기 
 - Market(시장가): 즉시 체결, 급변 시 불리할 수 있음 
5. Open Orders · Order History · Assets에서 체결·잔고 확인 

장기 보유·이체만이면 현물만으로도 충분하고, 굳이 선물을 켤 필요는 없다. 
데모에서 같은 흐름을 먼저 반복해 보는 편이 안전하다.

## 8. 선물(무기한) 사용법

메뉴 이름은 앱/웹·언어에 따라 다름. 개념: [[코인 현물과 선물]].

### 8.1 진입 전 설정

1. **Derivatives / 선물** → **USDT Perpetual**(또는 USDC 등) 
2. 심볼: `BTCUSDT`, `ETHUSDT` … 
3. 계정·마진: **Isolated**(연습) 
4. **레버리지** 낮게 (숫자가 클수록 청산이 가까워짐) 
5. Position mode: **One-way**(단순) / Hedge(양방향 — 복잡) 
6. **Take Profit / Stop Loss** 칸을 미리 염두 

### 8.2 주문

1. 방향: **Long(매수/롱)** 또는 **Short(매도/숏)** 
2. 주문 유형: Limit 또는 Market 
3. 수량(또는 금액) 입력 — **코인 수량 vs USDT 금액** 표시를 혼동하지 말 것 
4. 주문 확인 → Open Orders / Positions 

### 8.3 포지션 관리

| 볼 것 | 의미 |
|-------|------|
| Entry | 진입가 |
| Mark | 마크가 (청산 계산에 자주 쓰임) |
| Liq. Price | 예상 청산가 |
| Unrealized PnL | 미실현 손익 |
| MMR 등 | Cross에서 위험 지표 |

- Stop Loss는 청산가보다 **유리한(덜 아픈) 쪽**에 두는 설명이 흔함 
- 종료: **Close** / Reduce-only / 반대 주문 
- 펀딩비는 포지션 유지 중 주기적으로 오가므로, “차트만 이득”이어도 잔고가 깎일 수 있음 

### 8.4 대략 숫자

- 포지션 가치 ≈ 가격 × 수량 
- 필요 증거금 ≈ 포지션 가치 / 레버리지 (유지증거금·위험 한도는 별도) 

실전 전에 **Demo에서 진입→TP/SL→종료→(가상)청산 근처**까지 한 사이클을 돌려 본다.
