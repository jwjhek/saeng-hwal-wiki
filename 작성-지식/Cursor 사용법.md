# Cursor 사용법

> **분류:** 작성·지식 › 에디터·IDE · [[생활위키 목차]]

Cursor는 **VS Code를 포크한 에디터**에 AI 에이전트를 붙인 제품이다.  
파일 트리·검색·터미널·확장·단축키의 뼈대는 [[VS Code 사용법]]과 같고, 차이는 **Agent / Chat / Inline Edit / Tab 완성**으로 코드를 읽고 고치는 부분이다.

설치: [https://cursor.com](https://cursor.com)

아래 단축키는 Windows에서 `Ctrl` 기준. macOS는 대부분 `Cmd`.  
제품 업데이트로 바뀔 수 있으니, 명령 팔레트 → **Keyboard Shortcuts**에서 `Cursor`로 검색해 확인하는 것이 정확하다.  
공식 목록: [Keyboard Shortcuts](https://cursor.com/docs/reference/keyboard-shortcuts)

## 1. VS Code와의 관계

### 그대로 가져오는 것

- 폴더 워크스페이스
- `Ctrl + P` 파일 열기, `Ctrl + Shift + P` 명령 팔레트
- 탐색기 / 검색 / Git / 터미널 / 확장
- `settings.json`, 키바인딩, 많은 VS Code 확장

### Cursor가 더하는 것

| 기능 | 한 줄 설명 |
|------|------------|
| Tab | 타이핑 중 다중 줄 자동완성 |
| Inline Edit (`Ctrl + K`) | 선택 구간만 자연어로 수정 |
| Sidepanel (`Ctrl + I` / `Ctrl + L`) | 채팅·에이전트로 질문·다중 파일 작업 |
| @ 멘션 | 파일·폴더·문서 등을 프롬프트에 명시적으로 첨부 |
| 모드 (Agent / Ask 등) | “실행형” vs “질문형” 전환 |
| MCP / 규칙 / 스킬 | 외부 도구·프로젝트 규칙·반복 절차 (고급) |

이미 VS Code 사용자라면 **편집 감각은 유지한 채 AI 레이어만 배우면** 된다.

---

## 2. AI를 고르는 기준 — 무엇으로 할지

같은 “고쳐줘”라도 도구가 다르다.

| 상황 | 추천 | 이유 |
|------|------|------|
| 지금 보고 있는 함수/문단만 살짝 수정 | **Inline Edit** `Ctrl + K` | 범위가 작고 diff가 명확 |
| “이 코드가 왜 이래?” 설명·조사 | **Ask** 모드 | 읽기 위주, 실수 수정 범위가 좁음 |
| 여러 파일 생성·수정, 명령 실행 | **Agent** | 워크스페이스를 넘나들며 작업 |
| 타이핑 중 다음 줄 예측 | **Tab** | 리듬을 끊지 않음 |
| 위키 글 초안, 리팩터 계획 | Agent + 명확한 제약 | 파일 생성까지 한 번에 |

습관 규칙:

- **범위를 알면** Inline
- **범위가 넓거나 모르겠으면** Agent
- **일단 이해만** Ask

## 3. 사이드패널 (Chat / Agent)

### 열기

- `Ctrl + I` 또는 `Ctrl + L` — 사이드패널 토글  
  (설정에 따라 둘 다 Sidepanel에 묶여 있음)
- `Ctrl + E` — Agent 중심 레이아웃 토글
- `Ctrl + .` — 모드 메뉴
- `Shift + Tab` — 입력창에서 모드 순환
- `Ctrl + /` — 모델 전환
- `Ctrl + Shift + J` — Cursor 설정

### Agent vs Ask (실무적으로)

**Agent**

- 파일을 읽고, 수정하고, 터미널 명령을 제안·실행할 수 있다
- “이 기능 추가해줘”, “버그 고쳐줘”, “문서 세 개 작성해줘”에 적합
- 결과는 diff로 보이므로 **수락/거절**을 반드시 본다

**Ask**

- 설명, 비교, 원인 추정, 코드 리뷰 질문
- “왜 크래시가 나?”, “이 설정 의미가 뭐야?”
- 조사만 하고 싶을 때 실수 편집 범위를 줄인다

### 채팅 입력에서 자주 쓰는 키

| 동작 | 단축키 |
|------|--------|
| 강제 전송 | `Ctrl + Enter` (입력 중) |
| 메시지 큐에 넣기 | `Ctrl + Enter` (기본 nudge와 역할이 버전별로 다를 수 있음 — UI 힌트 확인) |
| 생성 취소 | `Ctrl + Shift + Backspace` |
| 제안 변경 전부 수락 | `Ctrl + Enter` (제안이 있을 때) |
| 제안 전부 거절 | `Ctrl + Backspace` |
| 선택 코드를 컨텍스트로 | `Ctrl + Shift + L` |
| 새 채팅 | `Ctrl + N` / `Ctrl + R` (포커스에 따라) |
| 채팅 탭 | `Ctrl + T` |

버전에 따라 Enter가 “전송”이 아니라 “nudge”인 경우가 있다. 입력창 근처 안내 문구를 보면 된다.

## 4. Inline Edit (`Ctrl + K`)

에디터에서 코드를 선택한 뒤 `Ctrl + K` → 짧게 지시 → Enter.

예:

- `변수명을 더 명확하게`
- `에러 처리 추가`
- `이 문단을 초보자용으로 다시 써줘`
- `타입 에러 나게 하지 말고 수정`

팁:

- **선택을 정확히** — 선택 밖은 안 건드리는 편이 안전하다
- 한 번에 여러 요구를 넣지 말고, 한 지시씩
- 취소용 `Ctrl + Shift + Backspace`
- `Alt + Enter` — 빠른 질문(버전에 따라 Ask quick question)

부분만 고치는 습관이 Agent에게 “프로젝트 전체 마음대로” 맡기는 것보다 사고율이 낮다.

## 5. Tab 자동완성

타이핑하다 흐릿하게 제안이 나오면:

| 동작 | 키 |
|------|-----|
| 전체 수락 | `Tab` |
| 다음 단어만 수락 | `Ctrl + →` |
| 무시 | 그냥 계속 타이핑하거나 `Esc` |

Tab은 편하지만, **테스트·보안·라이선스에 민감한 코드**는 수락 전 한 줄씩 읽는다. 특히 API 키·비밀번호를 채워 넣는 제안을 경계한다.

## 6. 컨텍스트 — AI에게 “무엇을 보라”고 정해주기

AI 품질의 절반은 **프롬프트**, 절반은 **컨텍스트**다.

### @ 멘션

채팅 입력에 `@`를 치면 예를 들어:

- 특정 파일
- 폴더
- 문서
- 웹(기능이 열려 있을 때)
- 과거 채팅 등

“코드베이스 알아서 찾아봐”보다 **`@관련파일`을 붙이는 쪽**이 결과가 안정적이다.

### 선택 영역 보내기

1. 코드/텍스트 드래그
2. `Ctrl + Shift + L` → Chat에 컨텍스트로 추가  
   또는 Inline용 `Ctrl + Shift + K` (Add selection to Edit)

### 클립보드

코드를 복사한 뒤 채팅에서 붙여넣으면 참조로 넣는 동작이 있다.  
`Ctrl + Shift + V`는 “입력창에 텍스트로” 넣는 쪽에 가깝다 (버전별 UI 확인).

### 규칙 파일 / 프로젝트 지시

프로젝트에 규칙(예: `.cursor/rules`, 사용자 규칙, AGENTS.md 등)을 두면 “이 저장소에서는 이렇게”를 매번 말 안 해도 된다.  
위키라면 예:

- 마크다운 제목 스타일
- 노트는 **분류 폴더**에 둘 것 (`[[생활위키 목차]]` 맵)
- **한자 지양** (한글·영어 기술명). 법령·고유명 인용만 예외
- 한국어로 쓸지

## 7. 프롬프트를 잘하는 법

좋은 지시의 뼈대:

1. **목표** — 무엇을 만들고/고치나
2. **위치** — 어느 파일/폴더
3. **제약** — 하지 말 것, 스타일, 언어
4. **합격 기준** — 어떻게 되면 끝난 건지
5. **참고** — `@파일` 또는 “`OO.md` 톤으로”

### 나쁜 예

> 위키 좀 정리해줘

### 나은 예

> `생활위키`의 `작성-지식/`(또는 맞는 분류 폴더)에 `Git 사용법.md`를 새로 만들어줘.  
> `Obsidian 사용법.md`처럼 섹션을 나눠서, Windows + 터미널 초보자 기준으로.  
> 상단에 분류 줄을 넣고 `생활위키 목차.md` 목차에도 한 줄 추가해줘.  
> frontmatter는 넣지 마. Quartz/`docs` 쪽은 건드리지 마.

### 디버깅 예

> `@src/app.ts` 에서 로그인 후 리다이렉트가 두 번 된다.  
> 재현: /login → 성공 → /dashboard → 다시 /login.  
> 원인 후보를 나열한 뒤, 최소 수정으로 고치고 싶으니 Ask로 먼저 설명만.

## 8. diff 읽고 수락하기

Agent가 파일을 고치면 변경 diff가 뜬다.

- **전부 수락**하기 전에, 모르는 파일까지 바뀌지 않았는지 본다
- 큰 삭제·의존성 변경·설정 파일(`.env`, 배포 설정)은 특히 주의
- 마음에 안 들면 거절하고, “이 부분만, 이 방식으로” 다시 지시
- 터미널 명령 실행 제안은 **명령을 읽고** 허용

AI를 “자동 저장 버튼”으로 쓰지 말고 **리뷰어가 있는 주니어 동료**처럼 대하면 사고율이 떨어진다.

---

## 9. 터미널 + AI

통합 터미널에서 `Ctrl + K`를 누르면 **자연어 → 셸 명령** 프롬프트가 열린다.

| 동작 | 키 |
|------|-----|
| 명령 생성 | `Ctrl + K` (터미널 포커스) |
| 생성된 명령 실행 | `Ctrl + Enter` |
| 편집만 하고 실행은 보류 | `Esc` (버전에 따라 “Accept command without running”) |

에디터 Inline Edit와 **같은 키**이므로, 포커스가 터미널인지 에디터인지 확인한다.

위험 명령(`rm`, `git reset --hard`, 강제 push 등)은 생성됐더라도 실행 전 반드시 읽는다.

---

## 10. 모델·요금·속도

- `Ctrl + /`로 모델 순환 또는 피커
- 빠르고 싼 모델: 간단한 수정·초안
- 무거운 모델: 아키텍처, 난해한 버그, 긴 문서

채팅이 길어지면 컨텍스트가 흐려진다. **주제가 바뀌면 새 채팅**을 여는 편이 낫다.

---

## 11. 이 위키에서 Cursor 쓰는 흐름

생활위키를 Cursor로 연 뒤:

1. 새 글은 **분류 폴더**에 `.md`로 만든다 ([[생활위키 목차]] 맵)
2. frontmatter에 `publish` 넣기 ([[공개 규칙]])
3. 참고할 기존 글을 `@Obsidian 사용법.md`처럼 붙인다
4. Agent에게 초안 작성 지시
5. diff를 읽고 수정·수락
6. Obsidian으로 열어 위키링크·미리보기 확인
7. [[생활위키 목차]] 등 MOC에 링크 한 줄 추가

## 12. 자주 하는 실수

| 실수 | 대안 |
|------|------|
| “알아서 해줘”만 반복 | 목표·경로·제약을 문장으로 |
| 컨텍스트 없이 대규모 리팩터 | `@`로 범위 한정, 또는 Ask로 계획 먼저 |
| Tab 제안을 읽지 않고 수락 | 한 호흡 읽고 `Ctrl + →`로 부분 수락 |
| 긴 채팅 하나에 모든 주제 | 주제별 새 채팅 |
| 시크릿을 채팅에 붙여넣기 | `.env` 내용·키·토큰 금지 |
| VS Code와 단축키 혼동 | Cursor AI 키만 별도 치트시트로 기억 |

## 13. VS Code 단축키 + Cursor 치트시트 (요약)

### 공통 (VS Code)

| 동작 | 키 |
|------|-----|
| 명령 팔레트 | `Ctrl + Shift + P` |
| 파일 열기 | `Ctrl + P` |
| 전체 검색 | `Ctrl + Shift + F` |
| 터미널 | `Ctrl + `` ` `` |
| 설정 | `Ctrl + ,` |
| 줄 복제 | `Shift + Alt + ↓` |
| 다중 선택 | `Ctrl + D` |

### Cursor

| 동작 | 키 |
|------|-----|
| 사이드패널 | `Ctrl + I` / `Ctrl + L` |
| Inline Edit | `Ctrl + K` |
| 모드 메뉴 | `Ctrl + .` |
| 모델 전환 | `Ctrl + /` |
| Cursor 설정 | `Ctrl + Shift + J` |
| 선택 → Chat | `Ctrl + Shift + L` |
| Tab 수락 | `Tab` |
| 단어 단위 수락 | `Ctrl + →` |
| 변경 수락/거절 | `Ctrl + Enter` / `Ctrl + Backspace` |

더 많은 편집 단축키는 [[VS Code 사용법]] 참고.

## 14. 다음에 익히면 좋은 것

우선순위 낮은 순서대로, 필요할 때:

- **Rules / Memories** — 프로젝트·개인 취향 고정
- **MCP** — 외부 서비스(이슈 트래커, 브라우저 등) 연결
- **Skills / 자동화** — 반복 절차를 스킬로
- **Bugbot / 클라우드 에이전트** — PR·원격 작업 (쓰는 환경일 때)
- **확장** — VS Code 확장 대부분 호환, 충돌 시 하나씩 끄기

처음에는 Sidepanel + Inline + Tab + `@`만으로도 생산성이 크게 오른다.
