# Obsidian 사용법

> **분류:** 작성·지식 › 노트·지식 · [[생활위키 목차]]

로컬 마크다운 노트를 **연결해서** 키우는 앱. 클라우드 전용 위키가 아니라, PC 폴더(vault)가 곧 데이터다.

설치: [https://obsidian.md](https://obsidian.md)

---

## 1. 핵심 개념

### Vault (보관고)

Obsidian이 연 **폴더 하나**가 vault다.

- 노트 = 그 안의 `.md` 파일
- 이미지·PDF도 같은 폴더 트리에 두면 된다
- 앱을 지워도 폴더만 있으면 내용은 남는다

여러 vault를 둘 수 있다. 예: `생활위키`, `일기`, `업무`를 분리.

이 저장소를 vault로 쓸 때:

1. **Open folder as vault**
2. `생활위키` **루트**를 선택
3. 노트는 **분류 폴더**에 `.md`로 둔다 (목차는 루트 `[[생활위키 목차]]`)

### 폴더 vs 링크

Obsidian은 폴더 깊숙이 분류하는 것보다:

- `[[위키링크]]`로 글끼리 연결하고
- 태그로 느슨히 묶고
- **MOC(Map of Content)** 노트로 입구를 만드는

방식이 잘 맞는다. 폴더는 “대분류 몇 개”만 두고, 세부는 링크로 쓴다.

## 2. 화면과 기본 조작

| 영역 | 설명 |
|------|------|
| 왼쪽 | 파일 탐색기, 검색, 북마크 등 |
| 가운데 | 에디터 / 읽기 모드 |
| 오른쪽 | 아웃라인, 백링크, 태그 패널 등 (리본·사이드 설정에 따라 다름) |

자주 쓰는 단축키 (Windows, 기본값 — 설정에서 바뀔 수 있음):

| 동작 | 단축키 |
|------|--------|
| 명령 팔레트 | `Ctrl + P` |
| 빠른 전환 (노트 찾기) | `Ctrl + O` |
| 새 노트 | `Ctrl + N` |
| 전역 검색 | `Ctrl + Shift + F` |
| 그래프 뷰 | `Ctrl + G` |
| 편집/읽기 전환 | `Ctrl + E` |
| 위키링크 따라가기 | `Ctrl + 클릭` 또는 `Alt + Enter` (설정에 따라 다름) |

주의: VS Code/Cursor의 `Ctrl + P`는 **파일 열기**, Obsidian의 `Ctrl + P`는 **명령 팔레트**다. 헷갈리면 팔레트에서 `Quick switcher` / `빠른 전환`을 검색해 단축키를 확인한다.

## 3. 마크다운 치트시트

Obsidian은 CommonMark + 자체 확장(위키링크, callout 등)을 쓴다.

```markdown
# 제목 1
## 제목 2
### 제목 3

**굵게** *기울임* ~~취소선~~ `인라인 코드`

- 목록
  - 중첩
1. 번호 목록
2. 둘째

- [ ] 할 일
- [x] 완료

> 인용

[외부 링크](https://example.com)

| 열1 | 열2 |
|-----|-----|
| a   | b   |
```

코드 블록:

````markdown
```python
print("hello")
```
````

강조 박스(callout):

```markdown
> [!note] 제목
> 본문

> [!tip]
> 팁

> [!warning]
> 주의
```

자주 쓰는 callout 종류: `note`, `tip`, `warning`, `info`, `example`, `quote`.

## 4. 위키링크 — Obsidian의 심장

### 기본

```markdown
[[다른 노트 이름]]
[[다른 노트 이름|화면에 보일 텍스트]]
[[다른 노트#제목]]          ← 특정 헤딩으로
[[다른 노트#제목|표시]]
[[다른 노트^블록아이디]]     ← 블록 참조(고급)
```

`[[`만 입력하면 자동완성이 뜬다. **없는 이름을 링크하면** 나중에 클릭했을 때 새 노트를 만들 수 있다. “먼저 링크하고 나중에 쓰기”가 가능하다.

### 임베드 (내용 끼워 넣기)

```markdown
![[이미지.png]]
![[다른 노트]]
![[다른 노트#섹션]]
```

`!`를 붙이면 링크가 아니라 **내용을 현재 노트에 삽입**한다.

### 백링크

어떤 노트를 열면, 그 노트를 가리키는 다른 글 목록(백링크)을 볼 수 있다.  
“이 개념을 어디서 언급했지?”를 폴더 없이 역추적할 수 있다.

## 5. 태그

두 가지 방식이 있다.

본문:

```markdown
#windows #팁
```

속성(Properties / frontmatter):

```yaml
---
tags:
  - windows
  - 팁
---
```

권장:

- **주제·종류**는 태그 (`windows`, `obsidian`, `팁`)
- **고유한 한 글**은 제목 + 링크로 연결
- 태그를 너무 세분하지 않기 (`windows11-설정-디스플레이-밝기` 같은 건 링크/본문이 낫다)

태그 패널이나 검색 `tag:#팁`으로 모아볼 수 있다.

---

## 6. Properties (프론트매터)

노트 맨 위 YAML:

```yaml
---
title: 제목
date: 2026-08-06
tags:
  - tip
aliases:
  - 다른이름
cssclasses:
  - wide
---
```

용도:

- `aliases` — 다른 이름으로도 `[[다른이름]]` 링크 가능
- `tags` — 분류
- `date` / `created` / `updated` — 정렬·필터
- 플러그인·Bases(데이터베이스 뷰)의 필드

Obsidian UI에서도 속성 표를 편집할 수 있다. 명령 팔레트 → `Properties` 관련 명령.

---

## 7. 검색을 제대로 쓰기

빠른 전환(`Ctrl + O`): 제목·파일명 위주.  
전역 검색(`Ctrl + Shift + F`): 본문 전체.

검색 연산 예:

| 입력 | 의미 |
|------|------|
| `스크린샷` | 단순 포함 |
| `"정확히 이 구절"` | 구문 |
| `tag:#windows` | 태그 |
| `path:content` | 경로에 content 포함 |
| `file:.md` | 파일명 조건 |
| `-tag:#meta` | 제외 |

자주 쓰는 검색은 **북마크**하거나, 검색 결과를 저장하는 플러그인/코어 기능을 활용한다.

---

## 8. 그래프 뷰

`Ctrl + G`

- 점이 노트, 선이 링크
- 고립된 점(orphan) = 아무도 링크하지 않은 글 → 목차(MOC)에 넣을지 검토
- 로컬 그래프: 지금 노트 주변만 보기 (복잡할 때 유용)

그래프는 “예쁜 그림”보다 **연결이 빠진 글 점검**에 쓰는 편이 실용적이다.

---

## 9. MOC (목차 노트)

폴더 대신 **링크만 모아 둔 노트**를 입구로 쓴다.

예:

```markdown
# 생활위키 목차

## 에디터
- [[VS Code 사용법]]
- [[Cursor 사용법]]

## 노트
- [[Obsidian 사용법]]
```

새 글을 쓰면:

1. 글 작성
2. 관련 글에 `[[새글]]` 링크
3. MOC에도 한 줄 추가

이 세 가지를 습관화하면 “어디에 뒀는지 까먹는” 문제가 크게 줄어든다.

---

## 10. 템플릿

같은 형식을 반복할 때:

1. 설정 → 코어 플러그인 → **Templates** 켜기
2. 템플릿 폴더 지정 (예: `templates`)
3. 템플릿용 md 작성
4. 새 노트에서 명령 팔레트 → **Insert template**

템플릿에 쓸 수 있는 치환자 예 (버전에 따라 다름):

- `{{title}}`
- `{{date}}` / `{{date:YYYY-MM-DD}}`
- `{{time}}`

일상·회의록·위키 글처럼 **종류별 템플릿**을 2~3개만 두는 것이 유지보수에 유리하다.

---

## 11. Daily notes & 일기형 사용

코어 플러그인 **Daily notes**:

- 오늘 날짜 파일을 원클릭으로 생성
- 습관·메모·그날 한 일을 쌓기 좋음
- 날짜 노트에서 프로젝트 노트로 `[[링크]]`만 걸어 두면 “시간축”과 “주제축”이 동시에 생긴다

필수는 아니다. 위키형만 써도 충분하다.

---

## 12. Canvas

화이트보드처럼 카드·화살표를 놓는 뷰.

- 브레인스토밍
- 복잡한 관계 스케치
- 나중에 글로 정리하기 전 단계

파일 확장자는 `.canvas`. 남용하면 노트가 분산되니, “스케치 → 본 노트에 결론만 정리” 정도로 쓰는 것을 추천한다.

---

## 13. 첨부 파일·이미지

1. vault 안에 `attachments` 또는 `images` 폴더를 만든다
2. 설정 → 파일과 링크 → **기본 첨부 파일 위치**를 그 폴더로
3. 드래그 앤 드롭 또는 붙여넣기
4. `![[파일명.png]]`로 삽입

외부 경로에만 있는 이미지를 링크하면, 폴더를 옮기거나 다른 PC에서 깨지기 쉽다. **가능하면 vault 안으로**.

---

## 14. 플러그인

### 코어 플러그인 (공식, 비교적 안전)

설정 → 코어 플러그인에서 켜고 끈다.

유용한 것 예:

- Templates
- Daily notes
- Outgoing links / Backlinks
- Outline
- Page preview (링크 호버 미리보기)
- Slash commands
- Workspaces (화면 배치 저장)

### 커뮤니티 플러그인

설정 → 커뮤니티 플러그인 → 제한 모드 해제 후 검색.

원칙:

- **정말 필요한 것만**
- 최근 업데이트·다운로드 수 확인
- 모바일/동기화와 충돌할 수 있음
- 플러그인 전용 문법은 나중에 다른 툴로 보낼 때 깨질 수 있음

다른 도구와 공유할 가능성이 있으면 **표준 마크다운 + 위키링크 + callout** 정도에 문법을 가둬 두는 편이 안전하다.

## 15. 동기화

Obsidian 데이터는 로컬 폴더다. 동기화는 별도 선택:

| 방식 | 특징 |
|------|------|
| Obsidian Sync (유료) | 공식, 충돌 처리·암호화 옵션 |
| OneDrive / Dropbox 등 | vault 폴더를 동기화 폴더에 두기. 동시 편집 충돌 주의 |
| Git | 버전 관리에 강함. 모바일은 별도 앱/워크플로 필요 |
| iCloud | Mac/iOS에서 흔함. Windows와 섞을 때 주의 |

Windows에서 클라우드 동기화 폴더를 쓸 때:

- vault를 OneDrive **데스크톱/문서 하위**에 두면 경로가 길어지거나 잠금 문제가 날 수 있다
- 가능하면 동기화 충돌이 적은 방식(Git 또는 Sync)을 개인 습관에 맞게 고른다

## 16. 이 위키(생활위키)에서의 실전 배치

| 위치 | 용도 |
|------|------|
| 루트 `index.md` · `생활위키 목차.md` · `공개 규칙.md` | 홈·목차·공개 정책 |
| `PC-OS/` · `작성-지식/` · `AI/` · … | 본문 노트 (분류별) |
| `개발/언어/` 등 | 개발 하위 분류 |
| `templates/` | 템플릿 (Quartz 빌드 제외) |
| `private/` | 민감 메모 (gitignore) |
| `attachments/` 등 | 이미지·첨부 |
| `.obsidian/` | Obsidian 설정 |

작성 루틴 예:

1. 맞는 **분류 폴더**에 새 `.md` 작성 (`templates/` 참고)
2. `publish: true/false` 결정 — [[공개 규칙]]
3. 관련 글·[[생활위키 목차]]에 링크
4. 태그·백링크로 다시 찾을 수 있게 정리

폴더 맵은 [[생활위키 목차]] «분류 한눈에»를 본다.  
`[[위키링크]]`는 파일명 기준이라 폴더를 옮겨도 이름이 같으면 연결이 유지된다.

---

## 17. 추천 습관

1. **새 노트 = 링크 최소 1개** — 고립 노트 방지
2. **MOC·폴더를 같이** — 분류 폴더에 두고 목차 노트에 한 줄
3. **이름은 검색되게** — `메모1.md` 금지. `Windows 클립보드 기록.md`처럼
4. **한 노트 한 주제** — 너무 긴 만능 노트보다 연결
5. **주기적으로 orphan·깨진 링크 점검** — 그래프 + 검색
6. **플러그인 다이어트** — 분기마다 안 쓰는 것 제거
