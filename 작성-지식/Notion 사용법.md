# Notion 사용법

> **분류:** 작성·지식 › 노트·지식 · [[생활위키 목차]]

클라우드 기반 **페이지 + 데이터베이스** 워크스페이스. 
문서를 예쁘게 쌓는 도구이면서, 표·칸반·캘린더로 **업무·할 일·자료실**을 한곳에서 굴릴 때 강하다.

웹: [https://www.notion.com](https://www.notion.com) 
앱: Windows / macOS / iOS / Android 
단축키 공식: [Keyboard shortcuts](https://www.notion.com/help/keyboard-shortcuts)

아래는 Windows `Ctrl` 기준. 기능·UI는 플랜·업데이트에 따라 달라질 수 있다.

---

## 1. Notion이 잘 맞는 일 / 안 맞는 일

| 잘 맞음 | 덜 맞음 |
|---------|---------|
| 팀 공유 문서·회의록·위키 | 완전 오프라인·로컬 파일 소유가 최우선일 때 |
| 할 일·프로젝트·CRM 식 DB | 대용량 바이너리·정밀 diff |
| 템플릿·뷰로 같은 데이터를 여러 각도로 보기 | Git처럼 줄 단위 버전 관리 |
| 빠른 페이지·표 프로토타입 | 코드 프로젝트의 메인 에디터 |

이 vault([[Obsidian 사용법]])는 **로컬 마크다운**이고, Notion은 **서버에 있는 페이지**다. 
둘 다 “노트”지만 철학이 다르다. 전체 비교는 [[메모 앱]], 역할 나누기는 맨 아래 참고.

---

## 2. 핵심 개념

### 워크스페이스 (Workspace)

계정 아래의 작업 공간. 사이드바에 보이는 페이지 트리 전체. 
개인용 / 팀용을 나눌 수 있다.

### 페이지 (Page)

노트의 단위. 페이지 안에 또 페이지를 넣을 수 있다 (무한 중첩).

### 블록 (Block)

페이지를 이루는 조각. 문단, 제목, 목록, 이미지, 표, 임베드, **하위 페이지** 모두 블록이다. 
마우스로 왼쪽 `⋮⋮` 핸들을 드래그해 순서를 바꾼다.

### 데이터베이스 (Database)

같은 속성(프로퍼티)을 가진 **페이지들의 모음**. 
하나의 DB를 테이블·보드·캘린더·리스트·갤러리·타임라인 등 **뷰**로 바꿔 본다.

한 줄로 기억하면:

> 페이지 = 문서, 데이터베이스 = 속성이 있는 페이지 목록, 뷰 = 그 목록을 보는 방식

---

## 3. 처음 세팅

1. 가입 후 데스크톱 앱 또는 브라우저로 접속
2. 사이드바에서 **새 페이지** 만들기 (`Ctrl + N`, 앱 기준)
3. 아이콘·커버를 넣어 구분을 쉽게 (필수는 아님)
4. 자주 쓰는 페이지는 **즐겨찾기**에 고정
5. 설정에서 언어·시작 페이지·알림을 맞춘다

사이드바 구조 예:

```text
개인 홈
├── 📥 수신함 (임시)
├── ✅ 할 일 (데이터베이스)
├── 📒 회의록
├── 📚 자료 / 위키
└── 🗂 프로젝트들
```

처음부터 완벽히 나누지 말고, **수신함 → 나중에 분류** 흐름이 유지에 유리하다.

## 4. 글 쓰기 — 슬래시(`/`)가 전부다

빈 줄에서 `/`를 누르면 블록 메뉴가 뜬다. 이름을 이어서 치면 바로 고를 수 있다.

자주 쓰는 예:

| 입력 | 결과 |
|------|------|
| `/제목1` `/h1` | 큰 제목 |
| `/제목2` `/h2` | 중간 제목 |
| `/글머리` `/bullet` | 불릿 목록 |
| `/번호` `/numbered` | 번호 목록 |
| `/할일` `/todo` | 체크박스 |
| `/토글` `/toggle` | 접기/펼치기 |
| `/구분선` `/div` | 가로선 |
| `/코드` `/code` | 코드 블록 |
| `/인용` `/quote` | 인용 |
| `/콜아웃` `/callout` | 강조 박스 |
| `/페이지` `/page` | 하위 페이지 |
| `/표` `/table` | 간단 표 (DB 아님) |
| `/이미지` | 이미지 |

마크다운 습관이 있으면 그대로도 된다:

- `#` + 스페이스 → 제목
- `-` + 스페이스 → 불릿
- `[]` + 스페이스 → 할 일
- `>` + 스페이스 → 인용
- `` ``` `` → 코드 블록
- `---` → 구분선

### 멘션·날짜·링크

| 입력 | 용도 |
|------|------|
| `@사람` | 사람 멘션 (알림) |
| `@오늘` `@날짜` | 날짜 멘션 |
| `@페이지이름` | 다른 페이지 멘션(링크) |
| `[[` 또는 `@` | 페이지 검색해 연결 |

외부 URL을 붙여넣으면 북마크·임베드·일반 링크 중 고를 수 있다.

## 5. 블록 다루기 (필수)

| 동작 | 단축키 / 방법 |
|------|----------------|
| 지금 블록 선택 | `Esc` |
| 블록 선택 (커서가 있을 때) | `Ctrl + A` (한 번) |
| 블록 복제 | `Ctrl + D` |
| 블록 종류/색 바꾸기 | 선택 후 `Ctrl + /` |
| 블록 위아래로 이동 | 선택 후 `Ctrl + Shift + ↑/↓` |
| 들여쓰기(중첩) | `Tab` / `Shift + Tab` |
| 삭제 | `Backspace` 또는 `Delete` |
| 링크로 페이지 열기 | `Ctrl + Enter` |

여러 블록을 `Shift + 클릭` 또는 `Shift + ↑/↓`로 골라 한꺼번에 이동·삭제·타입 변경할 수 있다.

토글·불릿 안의 중첩을 잘 쓰면 긴 회의록도 접어서 관리하기 좋다.

## 6. 페이지 탐색

| 동작 | 단축키 |
|------|--------|
| 빠른 찾기 (페이지 점프) | `Ctrl + P` 또는 `Ctrl + K` (버전에 따라 검색 UI) |
| 뒤로 / 앞으로 | `Ctrl + [` / `Ctrl + ]` |
| 새 페이지 | `Ctrl + N` |
| 새 창 | `Ctrl + Shift + N` |
| 다크 모드 토글 | `Ctrl + Shift + L` |

찾을 때는 사이드바를 헤매기보다 **빠른 찾기**가 기본이다. 
페이지 제목을 검색되게 짓는 것이 곧 정보 설계다. (`메모1` 금지)

## 7. 데이터베이스 — Notion의 본체

### 7.1 만들기

페이지에서:

- `/테이블` → 인라인 테이블 DB
- `/보드` → 칸반
- 또는 새 페이지를 **전체 페이지 데이터베이스**로 생성

인라인 = 문서 중간에 표가 끼어 있음. 
전체 페이지 = 그 페이지 자체가 DB.

### 7.2 속성 (Properties)

각 행(항목)은 사실 **페이지**이고, 열은 속성이다.

자주 쓰는 속성 타입:

| 타입 | 용도 |
|------|------|
| 제목 | 필수. 항목 이름 |
| 선택 / 다중 선택 | 상태, 태그, 우선순위 |
| 날짜 | 마감, 일정 |
| 사람 | 담당자 |
| 체크박스 | 완료 여부 |
| 숫자 | 금액, 점수 |
| URL / 이메일 / 전화 | 연락·링크 |
| 관계(Relation) | 다른 DB와 연결 |
| 롤업(Rollup) | 관계 맺은 DB에서 합계·개수 등 |
| 수식(Formula) | 계산된 값 |
| 파일 | 첨부 |
| 생성/수정 시간 | 자동 |

처음부터 속성을 많이 만들지 말고, **필터·정렬에 쓸 것 3~5개**만 두는 편이 유지된다.

### 7.3 뷰 (같은 데이터의 다른 얼굴)

| 뷰 | 언제 |
|----|------|
| 테이블 | 전체 목록·속성 편집 |
| 보드 | 상태 칸반 (할 일 → 진행 → 완료) |
| 캘린더 | 날짜 속성 기준 일정 |
| 리스트 | 가벼운 목록 |
| 갤러리 | 커버·이미지 중심 |
| 타임라인 | 기간이 있는 프로젝트 |

뷰마다 **필터·정렬·숨긴 속성·그룹**을 따로 둘 수 있다. 
예: “내 할 일” 뷰 = 담당자=나 AND 완료=아니오.

### 7.4 항목 열기

행을 열면 그 항목의 **상세 페이지**가 된다. 
Peek(미리보기)로 빠르게 넘길 때:

| 동작 | Windows |
|------|---------|
| 이전/다음 항목 | `Ctrl + K` / `Ctrl + J` |
| 닫기 | `Esc` |

여러 행을 선택한 뒤 `Ctrl + /`로 속성을 일괄 수정할 수 있다.

### 7.5 링크드 뷰 (Linked database)

같은 DB를 **다른 페이지에 필터된 모습으로** 다시 보여 준다. 
원본 데이터는 하나, 보여주는 창만 여러 개.

`/linked` 등으로 삽입. 
“프로젝트 페이지에는 그 프로젝트 할 일만” 같은 패턴에 필수다.

## 8. 템플릿

### 페이지 템플릿

DB 안의 파란 **New** 옆 화살표 → 템플릿. 
회의록·주간 리뷰·버그 티켓처럼 **매번 같은 뼈대**가 필요할 때.

템플릿에 `@오늘`, 기본 속성값, 체크리스트를 넣어 두면 클릭 한 번으로 채워진다.

### 템플릿 갤러리

Notion이 제공하는 공개 템플릿을 복제해 시작할 수 있다. 
다만 기능을 다 쓰기보다 **필요한 페이지만 남기고 삭제**하는 편이 낫다. 템플릿 과다 = 정리 부채.

---

## 9. 공유·권한·협업

- 페이지 오른쪽 위 **공유**로 사람·링크 초대
- 권한: 보기 / 댓글 / 편집 / 전체 허용 등
- 댓글: 드래그한 텍스트에 댓글, 또는 페이지 토론
- `@멘션`으로 알림

팀에서 쓸 때 규칙 예:

1. 임시 메모는 개인 영역, 확정본만 팀 위키로
2. DB 속성 이름·선택지 값은 함부로 안 바꿈 (뷰·필터가 깨짐)
3. 대시보드 페이지는 “링크드 뷰만”, 원본 DB는 한곳에

## 10. 가져오기·내보내기

| 방향 | 방법 |
|------|------|
| 밖으로 | 페이지 `⋯` → 내보내기 (Markdown & CSV, PDF, HTML) |
| DB | CSV로보내 표 도구에서 가공 가능 |
| 안으로 | 설정 → 가져오기 (Markdown, Confluence, Evernote 등) |

주의:

- Notion 전용 블록(일부 임베드·수식·관계)은 마크다운으로내면 **완전히 안 남을** 수 있다
- Obsidian으로 옮길 계획이면 처음부터 문단·제목·표 중심으로 쓰거나, 주기적으로보내 확인

이 생활위키(로컬 md)와 병행할 때:

- **장기 보관·로컬 소유** → Obsidian
- **공유·DB·대시보드** → Notion 
으로 나누면 이중이 덜하다.

## 11. AI·자동화 (있는 경우)

플랜에 따라 Notion AI로 요약·번역·초안을 도울 수 있다. 
API·Make/Zapier·공식 자동화로 DB 행 생성·알림도 가능하다.

처음에는 AI보다 **DB 구조·뷰·템플릿**을 안정시키는 편이 투자 대비이득이 크다.

## 12. 추천 워크플로

### 12.1 개인 할 일

1. DB 속성: 상태(선택), 마감(날짜), 영역(선택)
2. 보드 뷰 = 상태 기준
3. 테이블 뷰 = “이번 주 마감” 필터
4. 매일 수신함 페이지에 던져 두고, 하루 한 번 DB로 분류

### 12.2 회의록

1. 회의록 DB (날짜, 참석자, 관련 프로젝트 관계)
2. 템플릿: 안건 / 결정 / 액션 아이템
3. 액션은 할 일 DB로 관계 연결하거나 `@`로 할 일 페이지 멘션

### 12.3 팀 위키

1. 홈 페이지에 목차 + 링크드 뷰
2. 문서는 주제별 페이지, 메타는 태그·상태 속성
3. “작성 중 / 확정” 상태로 신뢰도 표시

### 12.4 과하게 만들지 않기

- DB를 수십 개로 쪼개기보다, **큰 DB + 뷰**가 관리하기 쉬운 경우가 많다
- 관계가 3단 이상 얽히면 수식·롤업 디버깅 비용이 커진다
- 사이드바에 페이지가 넘치면 아카이브(또는 보관용 토글)로 숨긴다

## 14. Obsidian·Cursor와 역할 나누기

```text
Notion ── 공유, DB, 대시보드, 팀 위키
Obsidian ── 로컬 소유, 위키링크, 장기 개인 지식
Cursor ── 코드·로컬 md 초안·일괄 수정
```

| 하고 싶은 일 | 추천 |
|--------------|------|
| 팀과 같이 표로 업무 관리 | Notion |
| 개인 사용법을 파일로 쌓기 | Obsidian (이 vault) |
| 긴 글 초안을 AI로 | Cursor → 필요 시 Notion에 붙여넣기 |
| 오프라인·폴더 백업이 중요 | Obsidian + WinMerge/Git |

Notion만으로 모든 걸 해결하려 하면 로컬 위키의 장점(단순 md, 툴 독립)이 사라진다. 
반대로 Obsidian만으로 팀 칸반을 흉내 내면 DB·권한에서 Notion만 못하다.

## 15. 자주 하는 실수

| 실수 | 대안 |
|------|------|
| 페이지를 폴더처럼 끝없이 중첩 | 검색 + DB + 즐겨찾기 |
| 속성 30개짜리 DB | 주 3~5개만, 나머지는 본문에 |
| 템플릿을 잔뜩 복제만 | 하나 정착 후 나머지 삭제 |
| 사이드바 = 유일한 목차 | 홈 대시보드 페이지를 입구로 |
| 중요 자료를 Notion에만 | 주기적보내 또는 로컬 병행 |
| 관계·수식을 처음부터 | 표+선택+날짜가 안정된 뒤 |
