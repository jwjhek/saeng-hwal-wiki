# WinMerge 사용법

> **분류:** 작성·지식 › 비교·이미지 · [[생활위키 목차]]

Windows에서 **두 파일·두 폴더의 차이를 보고, 한쪽 내용을 다른 쪽으로 복사(병합)** 하는 무료 도구.  
백업 대조, 배포 전 확인, “이 폴더랑 저 폴더 뭐가 다르지?”에 특히 잘 맞는다.

설치: [https://winmerge.org](https://winmerge.org)  
매뉴얼: [https://manual.winmerge.org](https://manual.winmerge.org)

---

## 1. 언제 쓰나

| 상황 | WinMerge로 하는 일 |
|------|-------------------|
| 백업 USB와 PC 폴더 | 빠진 파일·바뀐 파일 목록 확인 후 복사 |
| 배포 전/후 폴더 | 빌드 결과·설정이 의도대로인지 대조 |
| 두 버전의 설정 파일 | ini, json, yaml 줄 단위 diff |
| 문서 초안 vs 최종본 | 텍스트 변경 구간만 빠르게 훑기 |
| Git 없이도 간단히 | 버전 관리 대신 “폴더 A vs 폴더 B” |

Git/`git diff`와 겹치는 면도 있지만, WinMerge는 **탐색기에서 폴더 두 개를 집어 넣는 UI**가 강하고, 바이너리·대량 파일 목록 비교에도 자주 쓰인다.

에디터 안의 diff(VS Code·Cursor 소스 제어)는 “지금 워크스페이스의 변경”에 가깝고, WinMerge는 **임의 두 경로**를 붙이는 데 편하다.

---

## 2. 설치·실행

1. [winmerge.org](https://winmerge.org)에서 설치 파일 받기
2. 설치 중 **탐색기 컨텍스트 메뉴** 통합을 켜 두면 편하다  
   → 폴더/파일 우클릭 → WinMerge로 비교
3. 실행 파일 이름은 보통 `WinMergeU.exe` (유니코드)

한국어 UI: `보기(V) → 언어` 또는 설치 시 언어 선택. 메뉴 이름은 언어에 따라 `File/파일`, `Edit/편집`처럼 달라질 수 있다. 아래는 의미 기준으로 적는다.

---

## 3. 기본 흐름 (파일 비교)

1. `파일 → 열기…` (또는 `Ctrl + O`)
2. **1번 경로**(왼쪽), **2번 경로**(오른쪽)에 각각 파일 지정
3. 확인 → 좌우 분할 창에 내용과 차이 표시
4. 차이 구간을 이동하며 확인
5. 필요한 줄을 왼쪽←오른쪽 또는 왼쪽→오른쪽으로 복사
6. 수정한 쪽을 **저장** (`Ctrl + S`)

색으로 표시되는 일반적인 의미(테마에 따라 다를 수 있음):

- 한쪽만 있는 줄 / 다른 내용인 줄 → 강조 배경
- 같은 줄 → 평범하게 표시
- 차이 막대(옆 스크롤 옆)로 파일 전체에서 어디가 다른지 한눈에 파악

---

## 4. 폴더 비교 (가장 많이 쓰는 기능)

### 4.1 열기

1. `파일 → 열기…`
2. 1번·2번에 **폴더** 경로 지정 (파일 말고 폴더)
3. 옵션 확인:
   - **하위 폴더 포함** — 재귀 비교. 백업·프로젝트 통째 대조 시 거의 필수
   - **필터** — `*.obj;*.exe` 같은 건 빼기, 또는 필터 파일로 규칙 지정
4. 확인 → **폴더 비교 창**에 파일 목록이 뜬다

### 4.2 목록에서 읽는 법

행마다 대략 이런 상태가 있다 (표시 문구·아이콘은 버전·설정에 따라 다름):

| 상태 | 의미 |
|------|------|
| 동일 | 양쪽 내용이 같음 |
| 다름 | 양쪽 다 있지만 내용 또는 크기가 다름 |
| 왼쪽만 / 오른쪽만 | 한쪽에만 존재 |
| 바이너리 | 텍스트로 줄 비교하기 어려운 파일 |

정렬·필터로 “다른 것만” 보이게 하면 작업이 빨라진다.  
메뉴의 보기/필터 관련 항목에서 **동일한 항목 숨기기** 등을 켠다.

### 4.3 파일 내용까지 보기

목록에서 행을 더블클릭하거나 `Enter` → 그 파일의 **파일 비교 창**이 열린다.

### 4.4 폴더 단위로 맞추기 (복사)

폴더 비교에서 선택한 항목을:

| 동작 | 단축키 |
|------|--------|
| 왼쪽 → 오른쪽 복사 | `Alt + →` |
| 오른쪽 → 왼쪽 복사 | `Alt + ←` |
| 다음/이전 다른 항목 | `Alt + ↓` / `Alt + ↑` |
| 다시 스캔 | `F5` |

**어느 쪽이 “정본”인지** 먼저 정하고 한 방향으로만 복사하는 습관이 안전하다.  
양쪽으로 뒤섞어 복사하면 어느 쪽이 최신인지 금방 헷갈린다.

우클릭 메뉴에도 Copy Left / Copy Right, 삭제, 이름 바꾸기 등이 있다.

---

## 5. 파일 비교에서 차이 이동·병합

### 5.1 차이 점프

| 동작 | 단축키 |
|------|--------|
| 다음 차이 | `F8` 또는 `Alt + ↓` |
| 이전 차이 | `F7` 또는 `Alt + ↑` |
| 첫/마지막 차이 | `Alt + Home` / `Alt + End` |
| 줄 단위 차이 강조 | `F4` / `Shift + F4` |
| 왼쪽/오른쪽 창 포커스 | `F6` / `Shift + F6` |
| 새로고침 | `F5` |
| 다시 불러오기 | `Ctrl + F5` |

### 5.2 차이 복사 (병합)

| 동작 | 단축키 |
|------|--------|
| 왼쪽 → 오른쪽 | `Alt + →` |
| 오른쪽 → 왼쪽 | `Alt + ←` |
| 복사 후 다음 차이 | `Ctrl + Alt + →` / `Ctrl + Alt + ←` |
| 실행 취소 | `Ctrl + Z` |
| 다시 실행 | `Ctrl + Y` |
| 병합 모드 토글 | `F9` |

저장을 눌러야 디스크에 반영된다. 창만 닫으면 안 저장된 변경이 날아갈 수 있으니 주의.

### 5.3 3-way 병합

WinMerge는 **세 경로**(조상 / 내 쪽 / 상대 쪽) 비교도 지원한다.  
Git 머지 충돌을 외부 도구로 풀 때 쓰이곤 한다.  
평소에는 2-way(좌·우)만으로도 충분하다.

---

## 6. 필터 — 노이즈 줄이기

폴더 비교 시 `node_modules`, `.git`, 빌드 산출물까지 다 보면 느리고 산만하다.

방법:

1. 열기 대화상자의 **필터** 칸  
   예: 특정 확장만 보기 / 제외 패턴
2. `도구 → 필터…` 등에서 **필터 파일** 선택·편집  
   include / exclude 규칙을 여러 줄로 관리

추천 제외 예 (프로젝트에 맞게 조절):

- `.git\`
- `node_modules\`
- `__pycache__\`
- `*.exe`, `*.dll`, `*.pdb` (텍스트 비교가 목적일 때)
- `Dist\`, `build\`, `.next\` 등 생성물 폴더

“백업 동기화”가 목적이면 제외를 최소화하고, “소스만 대조”면 생성물을 적극 제외한다.

## 7. 탐색기·명령줄에서 바로 열기

### 7.1 탐색기

컨텍스트 메뉴가 설치된 경우:

1. 첫 파일/폴더 선택
2. `Ctrl`로 두 번째 선택
3. 우클릭 → WinMerge 관련 항목

또는 하나를 보낸 뒤 WinMerge 안에서 반대쪽 경로를 지정.

### 7.2 명령줄

설치 폴더의 `WinMergeU.exe` 예:

```text
WinMergeU.exe "C:\path\left" "C:\path\right"
```

폴더 비교·옵션 스위치는 공식 매뉴얼 **Command line** 절을 참고.  
스크립트나 배치 파일에서 “배포 전 자동으로 diff 창 띄우기”에 쓸 수 있다.

---

## 8. 설정해 두면 좋은 것

`편집 → 옵션` (또는 `도구 → 옵션`, 버전에 따라 위치 다름)

| 항목 | 추천 방향 |
|------|-----------|
| 공백 / 탭 / 줄끝(CRLF·LF) 무시 | 소스 비교 시 필요하면 켜기. 문서·설정은 끄는 편이 안전할 때도 있음 |
| 대소문자 무시 | 코드 언어·OS에 따라 |
| 폴더 비교 방식 | 크기·날짜만 vs 내용 비교. **내용 비교가 정확**, 대신 느림 |
| 백업 파일 만들기 | 병합 전 원본 보존용 |
| 외부 편집기 | VS Code/Cursor 경로를 지정해 “이 파일 에디터로 열기” |
| 동일한 항목 숨기기 | 폴더 비교 기본 보기를 깔끔하게 |

인코딩: 한글 텍스트가 깨지면 파일 비교 중 인코딩/코드 페이지를 맞춘다.  
UTF-8과 CP949(완성형)가 섞인 구형 문서는 특히 확인.

## 9. 실전 시나리오

### 9.1 USB 백업과 PC 동기화

1. 왼쪽 = PC의 정본 폴더, 오른쪽 = USB
2. 하위 폴더 포함 켜고 비교
3. 동일한 항목 숨기기
4. “왼쪽만 있음” → USB로 복사 (`Alt + →`)
5. “다름” → 파일 비교로 열어 최신 쪽 확인 후 복사
6. 삭제가 의도인지 확인한 뒤에만 한쪽에서 삭제

### 9.2 설정 파일 한 개만

1. 파일 vs 파일로 연다
2. `F8`로 차이만 순회
3. 필요한 키·값만 한쪽으로 복사
4. 저장 후 앱에서 설정 다시 로드

### 9.3 “어제 폴더” vs “오늘 폴더”

날짜가 다른 두 스냅샷 폴더를 통째 비교.  
Git 히스토리 대신 폴더 복사본만 있는 환경에서 유용하다.

### 9.4 Git과 같이 쓰기

- 일상 커밋 단위: VS Code / Cursor / `git diff`가 더 자연스럽다
- **워킹트리 밖** 두 디렉터리, 릴리즈 zip vs 현재 트리, 고객 배포본 대조 → WinMerge

Git 외부 diff/merge 도구로 WinMerge를 등록할 수도 있다. (git config의 `difftool` / `mergetool`)

## 10. 단축키 요약

### 폴더 비교

| 키 | 동작 |
|----|------|
| `Enter` | 선택 항목 열기 |
| `F5` | 폴더 다시 스캔 |
| `Alt + ↓` / `↑` | 다음/이전 다른 항목 |
| `Alt + Home` / `End` | 첫/마지막 다른 항목 |
| `Alt + →` / `←` | 왼쪽→오른쪽 / 오른쪽→왼쪽 복사 |

### 파일 비교

| 키 | 동작 |
|----|------|
| `F7` / `F8` | 이전/다음 차이 |
| `Alt + →` / `←` | 차이 복사 |
| `Ctrl + Alt + →` / `←` | 복사 후 다음 차이 |
| `F6` | 반대쪽 창으로 포커스 |
| `F9` | 병합 모드 |
| `Ctrl + S` | 저장 |
| `Ctrl + Z` / `Y` | 실행 취소 / 다시 실행 |

전체 목록: [Shortcut keys](https://manual.winmerge.org/en/Shortcut_keys.html)

## 11. 주의할 점

1. **복사 방향** — `Alt + →`가 “왼쪽을 오른쪽으로”인지 화면 배치를 매번 확인
2. **저장** — 병합 ≠ 자동 저장
3. **바이너리** — 이미지나 exe는 “다름”만 알고, 줄 단위 병합은 텍스트에 집중
4. **대용량·네트워크 경로** — 내용 비교는 시간이 걸린다. 필터·하위폴더 범위를 줄일 것
5. **권한** — Program Files 등은 관리자 권한·읽기 전용 때문에 복사가 실패할 수 있음
6. **원본 파괴** — 중요한 폴더는 병합 전 복사본을 하나 더 두거나 백업 옵션을 켠다

## 12. 다른 도구와 역할 나누기

| 도구 | 강점 |
|------|------|
| [[VS Code 사용법\|VS Code]] / [[Cursor 사용법\|Cursor]] | 프로젝트 안 변경, Git diff, 편집까지 한곳에서 |
| WinMerge | 임의 두 경로·폴더 트리 대조, 탐색기 연동, 빠른 좌우 복사 |
| Obsidian | 노트 내용 비교 용도는 아님. 링크·작성용 |

“폴더 두 개가 얼마나 다른지”가 먼저면 WinMerge → 필요한 파일만 에디터로 열어 수정.
