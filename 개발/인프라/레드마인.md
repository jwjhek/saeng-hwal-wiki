# 레드마인

> **분류:** 개발 › 인프라 · [[생활위키 목차]]

**레드마인**(Redmine)은 **오픈 소스** 프로젝트 관리·**이슈 트래킹** 웹 앱이다. 
티켓(일감)·일정·위키·게시판·**시간 기록**을 프로젝트 단위로 묶고, **Git·SVN** 저장소와 연결해 커밋·리비전을 이슈에 붙이는 구성이 흔하다.

Git 호스팅 자체는 [[GitHub]]·[[GitLab]] 영역이고, 레드마인은 **“무엇을 할지·누가·언제까지”** 를 적는 **협업 보드**에 가깝다. 
국내 **공공·SI·구축 프로젝트**에서 Jira 대신·병행으로 쓰이는 경우가 많다.

공식: [https://www.redmine.org](https://www.redmine.org)  
가이드: [https://www.redmine.org/guide](https://www.redmine.org/guide)

확인일: 2026-08-11

관련: [[Git 사용법]] · [[GitHub]] · [[GitLab]] · [[전자정부프레임워크]] · [[Notion 사용법]]

---

## 1. 개요

| 항목 | 설명 |
|------|------|
| 무엇 | **이슈(티켓)** 중심 프로젝트 관리. 버전·마일스톤·Gantt·캘린더 |
| 라이선스 | **오픈 소스**(GPLv2). 자체 서버에 **무료** 설치 가능 |
| 기술 | **Ruby on Rails**. DB는 MySQL·PostgreSQL·SQLite 등 |
| 배포 | 회사·기관 **셀프호스트**가 일반적. SaaS 대신 **직접 운영** |
| Git | 저장소 **연동**(커밋 메시지에 `#123` 등으로 이슈 참조) |
| 위키 | **프로젝트별** 위키 (이 생활위키·[[Obsidian 사용법]]과는 별개) |

```text
요구사항·버그·작업
 ↓ 이슈 등록·담당·상태
 ↓ 버전(마일스톤)·우선순위
 ↓ Git 커밋/브랜치와 연결 (선택)
 ↓ 완료·시간 기록·보고
```

---

## 2. [[GitHub]]·[[GitLab]]·Jira와 구분

| | 레드마인 | [[GitHub]] / [[GitLab]] | Jira (Atlassian) |
|--|----------|-------------------------|------------------|
| 정체 | **이슈·일정·위키** 통합 | Git **원격** + PR/MR + (CI) | **이슈·애자일** 상용 |
| Git 호스팅 | **연동만** (별도 서버) | **핵심 기능** | Bitbucket 등과 별도 |
| 비용 | 오픈 소스·자체 호스팅 | 무료 티어·유료 | **라이선스 과금** |
| 커스터마이즈 | **트래커·필드·워크플로**·플러그인 | 제한적(라벨·Projects) | 강함(유료) |
| 국내 | **공공·구축** SI에서 흔함 | 오픈소스·스타트업 | 대기업·해외 협업 |

```text
흔한 조합
 GitLab/GitHub (코드·MR) + 레드마인 (일감·WBS·공정)
 또는
 GitLab 하나로 이슈+CI까지 (레드마인 없음)
```

“Git만 쓰면 된다” vs “티켓·공정·감리 문서가 필요하다”에 따라 갈린다. [[전자정부프레임워크]]·공공 과제는 **레드마인+Git** 조합이 자주 나온다.

## 3. 핵심 개념

| 용어 | 설명 |
|------|------|
| **프로젝트 (Project)** | 이슈·위키·저장소가 묶인 **단위** (제품·고객사·팀별) |
| **이슈 (Issue)** | 버그·기능·작업 **티켓**. 번호 `#123` |
| **트래커 (Tracker)** | 이슈 **유형** — 버그, 기능, 지원, 일감 등 (이름·필드 커스텀) |
| **상태 (Status)** | 신규 → 진행 → 해결 → 종료 등 **워크플로** |
| **우선순위·심각도** | 긴급도·영향도 분류 |
| **버전 (Version)** | **마일스톤·릴리스** (v1.0, 2차 납품 등) |
| **카테고리** | 모듈·하위 시스템 구분 |
| **담당자·관람자** | Assignee, Watchers — 알림 |
| **관계** | 선행·후행·중복·연관 이슈 |
| **시간 기록** | 작업 **시간** 로그 (공수·청구·보고) |
| **저장소** | Git/SVN URL 연동 — **변경 집합**을 이슈에 표시 |
| **위키** | 프로젝트 문서 (요구사항·회의록 등) |
| **게시판·뉴스** | 공지·토론 |

이슈 목록·**필터·쿼리 저장**·CSV보내기로 “내 일감”“이번 주 마감” 뷰를 만든다.

## 4. 일하는 흐름 (개발자)

```text
1. 레드마인에서 이슈 #456 확인 (설명·첨부·댓글)
2. [[Git 사용법]]으로 브랜치 생성 (규칙: feature/456-… 등 팀 컨벤션)
3. 작업·커밋 — 메시지에 "refs #456" 또는 "fixes #456"
4. [[GitHub]]/[[GitLab]] MR·PR (코드 리뷰)
5. 머지 후 레드마인 이슈 상태 → 해결/종료, 시간 기록
6. 버전(마일스톤) 완료율·Gantt로 PM이 진척 확인
```

| 커밋 메시지 | 레드마인 동작 (설정에 따름) |
|-------------|---------------------------|
| `refs #123` | 이슈 #123에 **변경 집합** 링크 |
| `fixes #123` | 이슈 **상태를 해결**로 바꿀 수 있음 (키워드 설정) |

저장소가 GitLab에만 있고 레드마인은 **이슈만** 쓰는 팀도 많다. **어느 쪽이 진실(source of truth)** 인지 팀 규칙을 본다.

## 5. 화면·기능

| 기능 | 설명 |
|------|------|
| **이슈 목록** | 필터·정렬·컬럼. 저장된 쿼리 |
| **Gantt** | 일정·선행 관계 시각화 |
| **캘린더** | 마감·버전 일정 |
| **로드맵** | 버전별 이슈 묶음 |
| **위키** | 프로젝트 문서. 마크다운·텍스트 |
| **파일** | 이슈·문서 **첨부** |
| **시간 기록** | 공수 집계·보고서 |

관리자는 **역할·권한**(프로젝트별), **커스텀 필드**, **워크플로**(상태 전이 규칙)를 설정한다.

## 6. 설치·운영 (개요)

레드마인은 **직접 서버에 올리는** 경우가 대부분이다.

| 방식 | 메모 |
|------|------|
| **Linux + Ruby + DB** | 공식 설치 가이드. Nginx·Passenger/Unicorn 등 |
| **Docker** | 이미지·compose로 DB와 함께 — [[Docker 사용법]] |
| **업그레이드** | 버전·플러그인·DB **백업** 후 패치 |

| 운영 체크 | |
|-----------|--|
| 백업 | DB + `files/` 첨부 디렉터리 |
| 인증 | LDAP·OAuth·SAML 등 (플러그인·버전별) |
| HTTPS | 리버스 프록시·인증서 |
| 메일 | 이슈 알림 SMTP 설정 |
| 성능 | 대용량 첨부·이슈 수 — DB 튜닝 |

회사 **URL 하나**(예: `redmine.company.com`)에 프로젝트가 여러 개 있는 형태가 흔하다.

---

## 7. 플러그인·확장

레드마인은 **플러그인**으로 기능을 붙인다.

| 예시 방향 | 설명 |
|-----------|------|
| 보드·애자일 | 칸반 뷰 등 |
| 테스트·요구사항 | QA·추적성 |
| 테마·UI | 스킨 변경 |
| 인증·SSO | 기업 로그인 |
| API·연동 | 외부 도구·봇 |

플러그인은 **버전 호환**을 확인한다. 무분별 설치는 업그레이드 시 깨지기 쉽다.

## 8. [[Notion 사용법]]·[[Obsidian 사용법]]

| | 레드마인 | Notion / Obsidian |
|--|----------|-------------------|
| 목적 | **프로젝트 이슈·공정·감리** | 개인·팀 **노트·DB** |
| 이슈 번호 | `#123` **공식 티켓** | 없거나 자유 형식 |
| 워크플로 | **상태·권한** 엄격 | 유연 |
| Git 연동 | **커밋·변경 집합** | 약함 |

회의록은 Notion, **납품·버그·일감**은 레드마인처럼 **나누는** 팀도 있다. 이 **생활위키**는 Obsidian+Quartz이고, 레드마인 위키와 **역할이 다르다**.

---

## 9. 처음 쓸 때

| 할 일 | 설명 |
|------|------|
| 계정·프로젝트 권한 | 관리자에게 **멤버 등록** 요청 |
| **내 이슈** 쿼리 | 담당=나, 상태=진행 등 저장 |
| 알림 | 이메일·와처 설정 |
| 커밋 규칙 | `#이슈번호`·브랜치 이름 팀 문서 확인 |
| 첨부·댓글 | 요구사항 변경은 **이슈에 남기기** (카톡만 X) |
| 버전·마일스톤 | 어떤 **Version**에 넣는지 PM과 맞추기 |

[[Cursor 사용법]]·[[MCP]]로 이슈 트래커를 붙이는 팀도 있으나, **회사 정책**이 우선이다.

---

## 10. 실전 체크

- [ ] 이슈 번호·상태·담당을 **레드마인 기준**으로 맞췄는가  
- [ ] 커밋 메시지에 **refs/fixes** 규칙을 지키는가  
- [ ] 코드 리뷰는 [[GitHub]]/[[GitLab]], 진척 보고는 레드마인으로 **역할이 갈렸는가**  
- [ ] 마감·버전이 **Gantt/로드맵**과 일치하는가  
- [ ] 시간 기록·첨부를 **티켓에** 남기는가

## 11. 정리

| 항목 | 한 줄 |
|------|--------|
| 정의 | 오픈 소스 **이슈·프로젝트 관리** + 위키·일정 |
| Git | 호스팅이 아니라 **연동** — [[Git 사용법]]과 병행 |
| 비교 | [[GitLab]] 이슈+CI 일체형 vs 레드마인 **공정·커스텀** 강점 |
| 국내 | 공공·SI·구축에서 **자주** 접함 |
| 운영 | **셀프호스트**·플러그인·백업이 관리 포인트 |

## 면책

> **면책**  
> 레드마인·플러그인·회사 인스턴스 설정은 **버전·정책**마다 다르다. **사내 Redmine·관리자 가이드**가 우선이다.  
> 이 글은 제품 가입·도입 권유가 아니다.  
> 이슈·첨부에 **비밀번호·개인정보·고객 기밀**을 올리지 말 것 — 권한·보존 정책을 본다.
