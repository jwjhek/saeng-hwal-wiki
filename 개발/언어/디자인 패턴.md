# 디자인 패턴

> **분류:** 개발 › 언어 · [[생활위키 목차]]

**디자인 패턴**(design pattern)은 소프트웨어에서 **반복되는 설계 문제**에 대해, 검증된 **구조·역할·협력 방식**을 이름 붙여 정리한 것이다. 
1994년 **GoF**(Gang of Four) 책 *Design Patterns*가 널리 쓰이는 23가지를 정리했고, 이후 **아키텍처 패턴**, **동시성 패턴**, **도메인 패턴** 등으로 확장됐다.

이 글은 **개념·분류·자주 쓰는 패턴**을 [[Java 언어 학습]] 예시로 설명하고, [[Spring과 Spring Boot 학습]]·[[JDK]]에서 **어디에 보이는지**까지 연결한다. 
패턴 이름을 외우기보다 **“언제·왜 쓰는지”** 를 익히는 편이 낫다.

확인일: 2026-08-11

관련: [[Java 언어 학습]] · [[Spring과 Spring Boot 학습]] · [[전자정부프레임워크]] · [[Python 학습과 패키지]]

## 1. 개요

| 항목 | 설명 |
|------|------|
| 목적 | **변경에 강한** 구조, **역할 분리**, **재사용** |
| 형태 | 문제 맥락 + 해결 구조 + 결과(장단점) |
| GoF 23 | **생성·구조·행동** 3종으로 분류 |
| SOLID | 패턴의 **배경 원칙** — 특히 **DIP**(의존성 역전), **OCP**(개방-폐쇄) |
| 주의 | 패턴 **남용**은 코드만 복잡해짐. 문제가 있을 때만 |

```text
반복되는 설계 문제
 ↓
패턴 이름·구조로 소통
 ↓
인터페이스·역할로 결합도↓
 ↓
테스트·교체·확장이 쉬워짐 (이상적으로)
```

---

## 2. SOLID (패턴과 함께 볼 원칙)

| 원칙 | 한 줄 | 패턴과 |
|------|--------|--------|
| **S** 단일 책임 | 클래스는 **한 가지 이유**로만 바뀐다 | Facade·Service 분리 |
| **O** 개방-폐쇄 | 확장에는 열고 수정에는 닫는다 | Strategy·Template Method |
| **L** 리스코프 치환 | 하위 타입은 상위를 **대체** 가능 | 상속 설계 |
| **I** 인터페이스 분리 | 쓰지 않는 메서드에 끌려가지 않는다 | 작은 인터페이스 |
| **D** 의존성 역전 | 구체가 아니라 **추상**에 의존 | DI, Factory, Strategy |

[[Spring과 Spring Boot 학습]]의 **IoC/DI**는 DIP를 **프레임워크가 구현**해 주는 대표 사례다.

---

## 3. GoF 분류 요약

| 종류 | 역할 | 대표 패턴 |
|------|------|-----------|
| **생성 (Creational)** | 객체 **만드는** 방법을 캡슐화 | Singleton, Factory, Builder, Prototype |
| **구조 (Structural)** | 클래스·객체를 **조합** | Adapter, Decorator, Facade, Proxy, Composite |
| **행동 (Behavioral)** | 객체 **협력·책임 분배** | Strategy, Observer, Command, Template Method, State, Iterator |

아래는 **실무·Java·Spring**에서 자주 마주치는 것 위주다.

## 4. 생성 패턴 (Java)

### Singleton (싱글톤)

**인스턴스를 하나**만 두고 전역 접근점을 제공.

```java
public enum AppConfig {
 INSTANCE;
 private final Properties props = load();
 public String get(String key) { return props.getProperty(key); }
}
```

| | |
|--|--|
| 장점 | 자원 공유·일관성 |
| 단점 | **전역 상태**, 테스트·동시성 주의 |
| Java | `enum` 싱글톤이 **직렬화·리플렉션**에 상대적으로 안전하다고 알려짐 |
| Spring | 기본 **singleton** 스코프 — 컨테이너가 인스턴스 수 관리 |

남용하면 결합도가 올라간다. **상태 없는** 빈·설정에 한정하는 편이 낫다.

### Factory Method · Abstract Factory

**생성 로직**을 서브클래스·팩토리에 숨김. `new`가 흩어지지 않게.

```java
public interface PaymentFactory {
 Payment create();
}

public class CardPaymentFactory implements PaymentFactory {
 @Override public Payment create() { return new CardPayment(); }
}
```

| | |
|--|--|
| 쓸 때 | 구현체가 늘어나고, 호출부는 **인터페이스**만 알면 될 때 |
| Spring | `@Bean` 메서드, `FactoryBean`, Auto-configuration이 **팩토리** 역할 |

### Builder (빌더)

**필드가 많거나** 선택적 파라미터가 많을 때 단계적으로 생성.

```java
Order order = Order.builder()
 .customerId("c1")
 .item("book")
 .quantity(2)
 .build();
```

| | |
|--|--|
| Java | Lombok `@Builder`, **Record** + 정적 팩토리, `Stream` 파이프 |
| JDK | `StringBuilder`, `HttpRequest.newBuilder()` |
| 주의 | 불변 객체와 잘 맞음. **검증**은 `build()`에서 한 번에 |

### Prototype (프로토타입)

기존 객체를 **복제**해 새 인스턴스. `clone()` 또는 직렬화·복사 생성자.

Java에서 `Cloneable`은 설계가 애매해 **복사 생성자·팩토리**를 쓰는 팀이 많다.

## 5. 구조 패턴 (Java)

### Adapter (어댑터)

**호환되지 않는 인터페이스**를 맞춤. 레거시·외부 API 래핑.

```java
public class LegacyReportAdapter implements ReportExporter {
 private final LegacyReport legacy;
 public LegacyReportAdapter(LegacyReport legacy) { this.legacy = legacy; }
 @Override public byte[] export() { return legacy.dumpBytes(); }
}
```

### Decorator (데코레이터)

기능을 **겹겹이** 추가. 상속 대신 **같은 인터페이스**를 감쌈.

```java
public class LoggingRepository implements UserRepository {
 private final UserRepository delegate;
 public LoggingRepository(UserRepository delegate) { this.delegate = delegate; }
 @Override public User findById(Long id) {
 log.info("find {}", id);
 return delegate.findById(id);
 }
}
```

| | |
|--|--|
| vs 상속 | 조합으로 **런타임**에 기능 추가 |
| Java I/O | `new BufferedInputStream(new FileInputStream(...))` — 고전 예 |
| Spring | 트랜잭션·보안 **프록시**가 데코레이터에 가깝게 동작 |

### Facade (퍼사드)

복잡한 하위 시스템에 **단순한 진입 API** 하나.

```java
public class OrderFacade {
 private final InventoryService inventory;
 private final PaymentService payment;
 public void placeOrder(OrderRequest req) {
 inventory.reserve(req);
 payment.charge(req);
 }
}
```

컨트롤러 → 서비스 → 여러 리포지토리 흐름이 **퍼사드+레이어**에 가깝다.

### Proxy (프록시)

**대리 객체**가 접근을 제어. 지연 로딩·권한·로깅.

```java
// JDK 동적 프록시 개념 — 인터페이스 기반
InvocationHandler handler = (proxy, method, args) -> {
 log(method.getName());
 return method.invoke(target, args);
};
```

| | |
|--|--|
| Spring AOP | `@Transactional` 등은 **런타임 프록시**(JDK/CGLIB) |
| JPA | **Lazy** 연관이 프록시로 로딩되는 경우 많음 |

### Composite (컴포지트)

트리 구조를 **부분-전체** 동일하게 다룸. UI 컴포넌트, 폴더·파일.

```java
interface MenuComponent { void render(); }
class MenuItem implements MenuComponent { ... }
class MenuGroup implements MenuComponent {
 private final List<MenuComponent> children = new ArrayList<>();
}
```

## 6. 행동 패턴 (Java)

### Strategy (전략)

알고리즘(정책)을 **캡슐화**하고 런타임에 교체.

```java
public interface DiscountPolicy {
 int apply(int price);
}

public class OrderService {
 private final DiscountPolicy policy;
 public OrderService(DiscountPolicy policy) { this.policy = policy; }
 public int checkout(int price) { return policy.apply(price); }
}
```

| | |
|--|--|
| Spring | `Map<String, Handler>` + `@Component` 이름, **조건부 빈** |
| vs if-else | 분기가 늘면 **클래스로 분리** |

### Observer (옵저버)

상태 변경 시 **구독자**에게 알림.

| | |
|--|--|
| Java | `PropertyChangeListener`, **Reactive Streams** |
| Spring | `ApplicationEvent` + `@EventListener` |
| 주의 | 동기 이벤트 폭주·순환 참조 |

### Command (커맨드)

요청을 **객체**로 캡슐화. 실행·취소·큐·로그.

```java
public interface Command { void execute(); }

public class CreateOrderCommand implements Command {
 private final OrderService orders;
 private final OrderRequest req;
 public void execute() { orders.create(req); }
}
```

UI 액션, 작업 큐, **CQRS**의 명령 쪽과 맞닿는다.

### Template Method (템플릿 메서드)

골격은 **상위 클래스**에, 일부 단계만 **하위**에서 구현.

```java
public abstract class AbstractExporter {
 public final void export(Path path) { // template
 open(path);
 writeHeader();
 writeBody();
 close();
 }
 protected abstract void writeBody();
}
```

| | |
|--|--|
| Spring | `JdbcTemplate`, `RestTemplate` — **콜백**으로 변형 |
| 주의 | 상속 결합 — 가능하면 **전략+조합**으로 대체 검토 |

### Iterator (이터레이터)

컬렉션 순회를 **통일**.

```java
for (User u : users) { ... } // Iterable + Iterator
```

Java **Enhanced for**, `Stream`도 순회 추상화의 확장.

### State (상태)

상태마다 **행동을 클래스**로 분리. `switch` 남발을 줄임.

```java
interface OrderState { void pay(Order ctx); void ship(Order ctx); }
class PaidState implements OrderState { ... }
```

주문·결제·게임 FSM 등에 쓰인다.

### Chain of Responsibility (책임 연쇄)

요청을 **핸들러 체인**으로 넘김. 필터·미들웨어.

```java
public interface Filter {
 void doFilter(Request req, Response res, FilterChain chain);
}
```

Servlet `Filter`, Spring Security **필터 체인**이 대표적.

## 7. JDK·라이브러리에서 보는 패턴

| API | 패턴 |
|-----|------|
| `Collections.unmodifiableList` | Decorator |
| `Arrays.asList` | Adapter (뷰) |
| `ExecutorService` | Command + Pool |
| `Optional` | Null Object 변형 |
| `Stream.map/filter` | Strategy(람다) |
| `Comparator.comparing` | Strategy |
| `ServiceLoader` | Factory |

패턴을 **암기**하기보다 JDK 소스·문서를 읽을 때 “아, 이 구조구나” 정도면 충분하다.

## 8. Spring에서 보는 패턴

| Spring 기능 | 패턴에 가까운 것 |
|-------------|------------------|
| `@Autowired` 생성자 주입 | DIP, Factory(컨테이너) |
| `@Bean` | Factory Method |
| `@Transactional` AOP | Proxy, Decorator |
| `JdbcTemplate` | Template Method |
| `ApplicationEvent` | Observer |
| `HandlerInterceptor` | Chain of Responsibility |
| `FilterRegistrationBean` | Chain |
| MVC `Controller` → `Service` | Facade, Layered |

[[전자정부프레임워크]]도 레이어·공통컴포넌트가 **같은 패턴 언어** 위에 있다. eGov만 복사해 와도 **패턴 이름**을 알면 코드 읽기가 빨라진다.

## 9. 안티패턴·과용

| 피할 것 | 이유 |
|---------|------|
| **Singleton 남용** | 전역 상태·테스트 지옥 |
| **God Class** | SRP 위반 — Facade와 혼동 |
| **패턴을 위한 패턴** | 문제 없는데 Factory 3겹 |
| **상속 남용** | Template Method만으로 깊은 트리 |
| **인터페이스 1구현** | “미래 확장”만 보고 과설계 |

**리팩터링**으로 패턴이 **드러나게** 하는 경우가 많다. 처음부터 23개를 넣지 않는다.

## 10. 언제 어떤 패턴을 고를지 (실무)

| 상황 | 후보 |
|------|------|
| 구현체를 바꿔 끼워야 함 | Strategy, Factory + 인터페이스 |
| 생성이 복잡함 | Builder, Factory |
| 외부 API가 우리 인터페이스와 다름 | Adapter |
| 기능을 덧붙이되 원본 수정 불가 | Decorator, Proxy |
| 복잡한 모듈에 단순 API | Facade |
| 알고리즘·정책이 자주 바뀜 | Strategy |
| 워크플로 단계는 같고 일부만 다름 | Template Method |
| 상태에 따라 행동이 달라짐 | State |
| 이벤트로 느슨하게 연결 | Observer |
| 요청을 객체로 저장·취소 | Command |

[[Java 언어 학습]]에서 **인터페이스·조합**을 익힌 뒤 패턴을 보면 이해가 빠르다.

## 12. 실전 체크

- [ ] `new`와 `if-else`가 **한 클래스에 몰려** 있지 않은가  
- [ ] 테스트에서 **구현체를 바꿔 끼울** 수 있는가 (인터페이스·DI)  
- [ ] Singleton이 **상태**를 들고 있지 않은가  
- [ ] Spring `@Transactional`이 **프록시**라는 걸 알고 `this.` 호출을 피하는가  
- [ ] 패턴 이름만 쓰고 **문제 맥락** 설명이 없는 설계는 아닌가
