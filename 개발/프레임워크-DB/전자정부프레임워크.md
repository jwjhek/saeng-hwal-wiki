# 전자정부 표준프레임워크 (eGovFrame)

> **분류:** 개발 › 프레임워크·DB · [[생활위키 목차]]

대한민국 공공·행정 정보화에서 쓰는 **Java 기반 표준 개발 프레임워크**. 
공식 명칭은 **전자정부 표준프레임워크**, 줄여서 **표준프레임워크 / eGovFrame**.

- 포털: [https://www.egovframe.go.kr](https://www.egovframe.go.kr) 
- 개발 가이드(5.0): [https://www.egovframe.go.kr/docs/5.0/](https://www.egovframe.go.kr/docs/5.0/) 
- 라이선스: Apache License 2.0 계열로 공개·재사용

확인일: 2026-08-06 
버전·JDK·가이드는 포털 공지가 최신이다. 사업 버전(특히 **4.3 vs 5.0**)을 먼저 확인한다.

---

## 1. 왜 만들었나

공공사업마다 업체·프레임워크가 제각각이면:

- 유지보수가 어렵고 
- 게시판·로그인 같은 **공통 기능을 중복 개발**하고 
- 특정 벤더에 종속되기 쉽다 

표준프레임워크는 **Spring 중심의 공통 실행/개발 환경 + 공통컴포넌트**를 제공해, 사업 간 표준화·재사용·품질을 높이려는 목적이다. 
2009년 전후 1.0부터 시작해 지속적으로 오픈소스 스택을 업그레이드해 왔다.

---

## 2. 한 줄로 이해하기

> **Spring(+ MyBatis 등)을 공공 표준에 맞게 묶은 실행환경** 
> \+ **이클립스/도구 중심 개발환경** 
> \+ **게시판·포털·보안 등 공통컴포넌트** 
> \+ **운영·배치 가이드**

순수 Spring Boot 앱과 “아예 다른 언어”가 아니다. 
**패키징·명명·레이어·공통모듈·가이드**가 공공 SI 관례에 맞춰져 있다고 보면 된다.

---

## 3. 전체 구성 (4대 환경 + 공통컴포넌트)

```text
┌─────────────────────────────────────────┐
│ 공통컴포넌트 │ 게시판, 회원, 권한, 파일… 재사용 앱
├──────────┬──────────┬──────────┬────────┤
│ 개발환경 │ 실행환경 │ 운영환경 │ 관리환경 │
│ IDE·빌드 │ Spring등 │ 모니터링 │ 적용점검 │
│ 테스트 │ 런타임 │ 배포·배치│ 호환성 │
└──────────┴──────────┴──────────┴────────┘
```

| 구분 | 역할 |
|------|------|
| **실행환경 (Runtime)** | 앱이 실제로 돌아갈 때 쓰는 라이브러리·서비스 (IoC, MVC, 데이터접근, 보안 연계 등) |
| **개발환경 (Development)** | 구현·테스트·배포·형상을 돕는 도구 (전통적으로 Eclipse 기반, 최근 VS Code 확장 등) |
| **운영환경 (Operation)** | 서비스 운영을 위한 배치·모니터링·배포 관련 가이드/도구 |
| **관리환경** | 적용 점검, 호환성 확인, 교육·포털 지원 등 |
| **공통컴포넌트** | 그대로 가져가 커스터마이징하는 업무 모듈 모음 |

포털 **자료실 / 다운로드 / 버전별 OSS 구성**에서 버전에 맞는 구성을 내려받는다.

---

## 4. 실행환경 — 기술 스택

버전마다 OSS 버전이 다르다. 5.0 가이드 기준:

| 영역 | 내용 |
| --- | ------------------------------------------------- |
| 기반 | Spring Framework (5.0 가이드: Spring 6.x대), IoC, AOP |
| 웹 | Spring MVC, (버전에 따라) WebFlux |
| 데이터 | MyBatis / Spring Data Access, DataSource |
| 화면 | JSP·템플릿·프론트 패턴은 사업마다 (최근은 API+React 등 분리도 흔함) |
| 모바일 | 모바일 웹 패턴·디바이스 API 가이드 (Flutter 가이드 등이 추가되기도 함) |
| 기타 | 로깅, 국제화, 스케줄/배치, 보안 유틸 등 |

**핵심 패턴 (레이어)**

```text
Controller (또는 RestController)
 → Service / ServiceImpl (업무 로직, 트랜잭션)
 → DAO / Mapper (MyBatis XML 등)
 → DB
```

전자정부 사업에서는 패키지·클래스 접두어(`Egov…`), Exception 처리, 로깅, 트랜잭션 경계를 **가이드와 템플릿**에 맞추는 경우가 많다.

DB는 Oracle, Tibero, Cubrid, PostgreSQL, MySQL 등 사업마다 다르다. 
Oracle 튜닝은 [[Oracle DB와 튜닝]] 참고. 스키마 별칭·객체 이름은 [[Oracle 시노님]], SQL 플랜 강제는 [[Oracle 힌트]] (운영은 신중히).

## 5. 개발환경

### 전통

- **Eclipse** + 표준프레임워크 구현 도구(플러그인·템플릿) 
- Maven 기반 프로젝트 생성·빌드 
- 단위 테스트·배포·형상관리 도구 연계 가이드

### 최근 변화

- **IntelliJ**에서도 가이드에 따라 구성 가능 (버전별 안내) 
- **VS Code Extension** 제공 (5.0 공지 기준) 
- Spring Boot 친화적 parent/의존성 관리로 로컬 기동이 이전보다 수월해지는 추세 

5.0 개발환경 (가이드 표 기준, 변경 가능):

| 항목 | 5.0 | 4.3 |
|------|-----|-----|
| 개발용 JDK | 21 권장 | 17 권장 |
| 실행환경 | Jakarta EE, Servlet 5.0+ (Boot는 6.0+) | Java EE, Servlet 3.1+ |
| IDE | Eclipse 2025-03 등 | Eclipse 2024-03 등 |

**프로젝트 JDK와 WAS(Servlet) 스펙을 사업 제안요청서(RFP)·아키텍처에 맞게 고정**하는 것이 실무의 첫 단추다.

## 6. 공통컴포넌트

정보시스템에서 반복되는 기능을 **표준 코드로 제공**.

예 (종류·수량은 버전·패키지에 따라 다름):

- 게시판, 공지, 자료실 
- 사용자·권한·메뉴·코드 관리 
- 파일 업로드/다운로드 
- 일정, 설문, 포털 관련 
- 시스템 연동·보안 관련 유틸 

### 쓸 때 주의

1. **그대로 복붙 후 방치** → 보안 패치·XSS·업로드 취약점이 구버전으로 남음 
2. 화면·업무가 다르면 **과감히 줄이거나 재작성**하는 편이 나을 때도 있음 
3. 라이선스·가이드의 커스터마이징 범위를 지킨다 
4. 공통컴포넌트 DB 스키마와 사이트 표준 용어사전을 맞춘다 

“공통이니까 무조건 다 넣기”보다 **필요한 것만 적용 점검 기준에 맞게** 넣는 것이 유지보수에 유리하다.

## 7. 버전 흐름 (큰 그림)

| 계열               | 특징                                                                                                               |     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------- | --- |
| **3.x** (…~3.10) | Spring 4대, JDK 7~8 중심. 레거시 유지보수에 아직 많음                                                                           |     |
| **4.0~4.2**      | Spring 5, JDK 8+, REST·Swagger 연계 강화, WebFlux 시작                                                                 |     |
| **4.3**          | Boot 호환·보안·성능, 개발환경 JDK 17대                                                                                      |     |
| **5.0** (2026)   | **Jakarta EE** (`javax.*` → `jakarta.*`), Spring 6대, JDK 17+ / 개발 JDK 21, VS Code·AI RAG 예제·관측(Istio/OTel) 가이드 등 |     |

### 마이그레이션 포인트

- 3.x → 4.x: Spring·JDK·설정 방식(XML → Java Config 비중) 
- 4.x → 5.0: **패키지 네임스페이스 Jakarta 전환**이 가장 큼. 의존 라이브러리·WAS도 함께 
- 기존 시스템이 3.10이면 “한꺼번에 5.0”보다 **단계적(4.x 경유 또는 모듈 단위)** 검토 

포털의 **버전별 오픈소스 SW 구성**으로 정확한 jar 버전을 대조한다.

## 8. 전형적인 프로젝트 구조 (개념)

사업·템플릿마다 다르지만 흔히:

```text
egovframework
├── com / xxx ← 사이트 공통
├── let / us / … ← 업무 패키지 (명명은 사업 표준)
│ ├── web ← Controller
│ ├── service ← Interface / Impl
│ └── service/impl ← DAO·Mapper 호출
├── resources
│ ├── egovframework/mapper/**/*.xml
│ ├── spring/*.xml 또는 Java Config
│ └── message/*.properties
└── webapp / static ← JSP, JS, CSS (또는 프론트 분리)
```

설정 파일: DataSource, Transaction, Multipart, Interceptor(로그인·권한), Exception Resolver 등이 실행환경 관례를 따른다.

## 9. 개발자가 처음 할 일

1. 포털에서 **사업 지정 버전** 가이드·개발환경 다운로드 
2. JDK / Eclipse(또는 IntelliJ·VS Code) 맞추기 
3. 샘플(Hello / 템플릿)로 기동 확인 
4. DataSource를 로컬 DB에 연결 (`context-datasource` 등) 
5. 공통컴포넌트 중 게시판 하나 올려 보며 레이어 흐름 파악 
6. 로깅·예외·트랜잭션 경계를 팀 표준에 맞춤 
7. 정적 분석·시큐어코딩 (공공 필수 점검) 파이프라인 확인 

Maven parent 예 (5.0 가이드에 나오는 형태 — 버전은 문서 확인):

```xml
<parent>
 <groupId>org.egovframe.web</groupId>
 <artifactId>egovframe-web-config-parent</artifactId>
 <version>5.0.0</version>
</parent>
```

## 10. 장점·단점·현실

### 장점

- 공공 RFP·감리·**적용 점검**과 맞추기 쉬움 
- 공통컴포넌트로 초기 구축 속도↑ 
- Spring 생태계라 인력·자료가 상대적으로 많음 
- 오픈소스라 라이선스 장벽이 낮은 편 
- 버전 업그레이드로 보안·JDK 지원을 공식 경로로 따라갈 수 있음 

### 단점·제약

- 최신 민간 Spring Boot·Kotlin·MSA 스택보다 **무겁고 관례가 많음** 
- 공통컴포넌트 품질·UI가 사업 눈높이와 안 맞으면 비용↑ 
- Eclipse 중심 문화와 현대 IDE 워크플로 간극 (최근 개선 중) 
- 레거시(3.x)와 신규(5.0)가 현장에 섞여 **버전 파편화** 
- “표준”이라서 생기는 **형식 코드·설정 과다** 

### 현실적인 위치

- **공공 SI·행정망** → eGovFrame이 기본 선택인 경우 다수 
- **민간·스타트업·순수 API** → Spring Boot 단독이 더 흔함 
- 프론트는 eGov JSP 대신 **React/Vue + API**로 분리하는 사업이 늘고 있음 (백엔드만 표준프레임워크)

## 11. 보안·품질 (공공에서 특히)

- 시큐어코딩 가이드, SQL Injection / XSS / 파일 업로드 검증 
- 개인정보·암호화 모듈 (공통·사업 보안 요구) 
- 전자정부 프레임워크 **적용 여부·버전**이 산출물·점검 대상 
- 의존성 CVE: 포털 공지·OSS 업그레이드 노트 추적 
- 로그에 주민번호·비밀번호 남기지 않기 

공공·대형 SI에서는 **[[ISMS-P]]** 인증 범위에 맞춰 위 항목이 **증적**으로 요구되는 경우가 많다.

DB 성능은 프레임워크만으로 해결되지 않는다. 슬로우 SQL은 [[Oracle DB와 튜닝]] 절차로 본다.

## 12. 운영·배치·관측

- **배치**: 대용량 배치 프레임워크·가이드 (버전별) 
- **배포**: WAS(Jeus, Tomcat, WebLogic 등 사업 지정)에 war/boot jar 
- **5.0 공지 예**: Istio, OpenTelemetry 운영 가이드, AI RAG 예제 등 — 필요 사업만 도입 

로컬에서 설정·로그를 볼 때는 [[VS Code 사용법]], [[Cursor 사용법]], [[Notepad++ 사용법]]이 보조가 된다. 
긴 공식 PDF·가이드는 [[NotebookLM 사용법]]에 넣어 요약해도 좋다.
