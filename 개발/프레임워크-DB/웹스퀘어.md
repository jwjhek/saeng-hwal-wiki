# 웹스퀘어

> **분류:** 개발 › 프레임워크·DB · [[생활위키 목차]]

**웹스퀘어**(WebSquare)는 인스웨이브시스템즈의 **기업·공공용 HTML5 UI 플랫폼**이다. 검색·현장에서 **웹스케어**로 불리기도 한다. **공식 표기는 웹스퀘어.**

브라우저에서 돌아가는 **엔진**과, 화면을 그리는 **스튜디오**(이클립스 플러그인)로 나뉜다. React·Vue 같은 오픈 프론트 프레임워크가 아니라 **상용 라이선스** 제품이다. 백엔드는 보통 [[Spring과 Spring Boot 학습]]·[[전자정부프레임워크]]다.

공식: [https://inswave.com](https://inswave.com)  
개발 가이드(웹스퀘어5 SP5): [https://docs1.inswave.com/sp5_user_guide](https://docs1.inswave.com/sp5_user_guide)

확인일: 2026-08-18  
버전(5 / AI)·이클립스·JDK·eGov 호환 레벨은 **벤더 문서·사업 지정본**이 우선이다.

관련: [[전자정부프레임워크]] · [[Eclipse 사용법]] · [[Spring과 Spring Boot 학습]]

---

## 1. 개요

| 항목 | 설명 |
|------|------|
| **무엇** | 그리드·폼이 많은 **업무 화면**을 브라우저 표준으로 만드는 UI 도구 |
| **구성** | **스튜디오**(화면 XML 작성) + **엔진**(브라우저에 화면 표시) |
| **화면 파일** | 스튜디오가 만드는 **XML** 화면 + 스크립트. 일반 `.jsx` 앱과 워크플로가 다름 |
| **통신** | 페이지 새로고침 대신 **Submission**(Ajax)으로 서버와 JSON·XML 교환 |
| **데이터가 아님** | Spring·eGov·DB 그 자체. **화면 층**이다 |
| **오픈소스가 아님** | 라이선스·엔진 배포본·어댑터 jar는 **계약·사업** |

```text
브라우저 (웹스퀘어 엔진)
        ↕  Submission (HTTP Ajax)
WAS + Spring / 전자정부프레임워크
        ↕
DB ([[SQL 학습]] · Oracle 등)
```

옛 ActiveX·X인터넷과 달리, 근래 제품은 **No ActiveX, HTML5**를 내세운다. OSMU(한 소스·여러 단말) 안내가 있다.

---

## 2. 쓰는 이유

- 공공·금융 SI에서 **엑셀 같은 그리드**, 대량 조회·수정, 업로드/다운로드가 화면의 중심일 때.
- RFP·제안이 **특정 UI 솔루션**을 지정했을 때. 팀이 React를 좋아해도 사업 표준이 웹스퀘어면 그걸 쓴다.
- [[전자정부프레임워크]]와 **호환성 확인**(예: 4.2 레벨2 보도)이 있어, 행정망 사업에서 자주 묶인다.
- 디자이너가 아니라 **업무 화면 생산성**(WYSIWYG, 컴포넌트, 데이터 바인딩)을 노린다.

개인 토이 프로젝트·공개 웹앱의 기본 선택은 보통 **HTML + React/Vue**다. 웹스퀘어는 **라이선스가 있는 현장**용에 가깝다.

---

## 3. 스튜디오와 엔진

가이드 요지: 스튜디오로 화면 파일을 만들고, 엔진이 그 파일을 브라우저에 그린다.

| | 스튜디오 | 엔진 |
|--|----------|------|
| **역할** | 컴포넌트 배치, 스크립트, 미리보기·디버그 | 운영·개발 서버에서 화면 실행 |
| **바탕** | [[Eclipse 사용법]] 플러그인 안내가 기본 | WAS에 엔진·설정 XML을 배포 |
| **JDK** | 스튜디오가 요구하는 JDK는 **그 버전 안내서** | 서버 JDK는 사업·eGov와 맞춤 → [[JDK]] |

설정 파일 예: `client.config.xml`, `server.config.xml`. 값은 가이드·사업 템플릿.

화면을 다른 화면 안에 넣는 **WFrame**, 공통 조각 **UDC**(User Defined Component)가 있다.

---

## 4. 데이터와 통신 (현장 용어)

| 이름 | 하는 일 |
|------|---------|
| **DataCollection** | 화면 안 데이터 저장소 |
| **DataMap** | **한 건**(상세 폼) |
| **DataList** | **여러 건**(그리드 행). CRUD는 그리드가 아니라 **DataList API** 쪽이 맞다는 안내가 흔함 |
| **Submission** | 서버 호출. Reference(요청)·Target(응답)을 DataCollection에 연결 |
| **Grid / GridView** | DataList와 바인딩. 정렬·필터·엑셀 입출력 안내 |

서버는 전용 소켓이 아니라 **HTTP**다. JSON이면 `mediatype`을 JSON으로 두는 식이다. Spring Boot Jackson·eGov 연동용 **Data Adapter**(`websquare_adapter_*.jar`) 안내가 가이드에 있다. REST 개념은 [[API]].

동기 Submission은 비권장에 가깝고 **비동기**가 기본 안내인 경우가 많다.

---

## 5. 백엔드·전자정부와

웹스퀘어는 **컨트롤러가 아니다.** 레이어는 eGov와 같다.

```text
화면 XML (웹스퀘어)
 → Submission → Controller
 → Service → Mapper → DB
```

빌드는 사업이 [[Maven]]인 경우가 많다. 프론트를 React로 분리하는 사업과 **병행**되기도 한다. “eGov면 무조건 웹스퀘어”는 아니다. **RFP의 화면 기술**을 본다.

**웹스퀘어 AI**는 5에 AI 개발 보조를 붙인 제품군으로, eGov 호환 확인 보도가 있다. 기능·요금은 벤더.

---

## 6. 비슷한 제품과의 자리

한국 SI **업무 화면 솔루션**으로 같이 거론되는 이름이 있다. 우열 단정이 아니다.

| 쪽 | 메모 |
|----|------|
| **웹스퀘어** | HTML5 엔진 + 이클립스 스튜디오. 이 글 |
| **넥사크로 등** | 다른 벤더의 UI 플랫폼. Dataset·그리드 사상은 비슷하게 느껴질 수 있음 |
| **JSP + 공통컴포넌트** | eGov 기본 화면. 그리드 솔루션보다 단순 |
| **React / Vue + REST** | 공개 웹·SPA 인력 풀. 그리드·엑셀 관례는 라이브러리를 따로 씀 |

이직 때 “프론트”라고 적혀 있어도 **웹스퀘어 XML**이면 React 경력과 **1:1이 아니다.** 그리드·Submission·DataList를 별도로 익힌다.

---

## 7. 흔한 함정

| 증상 | 먼저 볼 것 |
|------|------------|
| 화면은 뜨는데 데이터가 없음 | Submission action URL, mediatype, Target DataCollection |
| 그리드만 고치고 저장이 안 됨 | 행 추가는 **DataList**. 그리드 display와 데이터 값이 다를 수 있음 |
| 이클립스만 빨갛다 | 엔진 버전·프로젝트 패스·JDK. [[Eclipse 사용법]] Maven Update |
| React처럼 라우터를 찾음 | WFrame·탭·SPA 옵션은 **웹스퀘어 방식** |
| 라이선스 워터마크·엔진 오류 | 계약 키·허용 도메인. 이 글이 우회를 안내하지 않음 |
| E2E가 안 잡힘 | 실제로는 HTML이다. [[Playwright]]는 가능하나 **생성 id·iframe(WFrame)** 을 본다 |
